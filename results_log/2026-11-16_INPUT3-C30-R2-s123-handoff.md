# INPUT3-C30 한 사이클 추가 — s1 / s2 / s3

요청: 현재 실험 완료 여부와 관계없이 각 서버에 현 A/B/C 실험을 한 사이클 추가한다.
새 Stage 1은 학습하지 않는다. 기존 C30를 보존하고 동일 recipe의 Student R2만 추가한다.

## 확인한 s1 상태

기존 `PANDA_S123_INPUT3_C30_20261115_v1`의 C/A/B는 모두 30,000 step COMPLETED.
각 run의 RR/FR 평가 JSON 30개를 확인했고, 기존 runner는 exit0으로 종료했다.
마지막 Sheet 게시 readback도 통과했다. 과거 40K A/B 결과도 보존돼 있다.
직전 세 C30 run은 학습 약4.55시간 + 평가 약0.84시간, 합계 약5.4시간이었다.
새 s1 사이클의 예상 시간도 비슷하지만 Sheet 통신·사전 점검 시간은 별도이다.

## 추가 큐: 각 서버 A→B→C

| 서버 | 데이터 | donor | 폭 | LR | 추가 실행 |
|---|---|---|---:|---:|---|
| s1 | WV3 | 기존 RGBN R1@27K |112|1.1e-4|A R2 30K → B R2 30K → C R2 30K|
| s2 | QB | 기존 RGBN R1@32K |128|1.0e-4|A R2 30K → B R2 30K → C R2 30K|
| s3 | GF2 | 기존 RGBN R2@42K |128|2.5e-4|A R2 30K → B R2 30K → C R2 30K|

A=원본 PAN, B=원본+corrected PAN, C=corrected PAN+(corrected−원본 PAN).
모두 interp23 MS를 함께 입력한다. 새 Student seed는261018102이며 A/B/C에서 공유한다.
R1의261018101과 다르다. 기존 weight의 추가 fine-tuning이 아니라 0 step부터 새 학습이다.
RGBN/Lanczos4/공통영역/D123/UBIL/scale1/α=β=0/γ=.25/q=0 예외처리를 모두 유지한다.
calibration은 기존 고정 donor의 캐시를 재사용한다.

## s2 / s3 실행

사용자가 push 후 서버 에이전트가 pull하고 다음 중 해당 서버 명령 하나를 실행한다.
이 문서 작성 세션에서는 원격 서버 프로세스를 직접 시작하지 않는다.

```bash
git pull --ff-only
python3 -m panda_input3_repeat.enqueue --server s2
```

```bash
git pull --ff-only
python3 -m panda_input3_repeat.enqueue --server s3
```

이미 실행 중인 원본-PAN 업로더/C30 runner는 중단하지 않는다. 새 R2 runner가
기존 C30 전체 큐 종료와 최종 게시 완료를 기다린 뒤 진행한다. 기존 큐가 미완료 상태로
중단돼 있으면 원래 launcher로 먼저 재개한다. `--check-only` 점검과 `--resume` 재개 지원.
같은 명령을 반복해도 추가 R3를 만들거나 기존 결과를 덮어쓰지 않는다.
