# [WIP] 새 서버(170hx) Teacher 기준선 (2026-08-24)

> **진행 중.** 끝나면 정식 문서로 대체하고 이 파일은 지운다 (`CONVENTION.md` §2).
> 원 개발 서버에서 도는 [두 축 결합 체인](2026-08-24_WIP_running.md)과는 **별개 실행**이다.

새 서버에 환경을 옮긴 뒤, **이 서버 전용 Teacher 기준선**을 만든다.
기존 `results_log` 의 Teacher 수치(2.1804 등)는 다른 GPU 에서 나온 값이라
이 서버 결과와 한 표에 넣을 수 없다 — 같은 설정 4벌의 폭이 이미 0.79% 다.

## 왜 이 config 인가

`pancrafter_wv3_fixed_valsel.yaml` — `fix_key_alias: True` / `fix_local_attn: True` / `select_on: val`.

기존 프루닝·ablation 43벌이 **전부 이 조건**(`fix_*: True`, val 선택)이다
([재현 감사 §1.4](2026-08-24_reproduction-audit.md)). 앞으로 이 서버에서 돌릴 축소 구성과
대응표본 비교를 하려면 기준선도 같은 조건이어야 한다.

배포본 그대로(`wv3_baseline`, `fix_*: False`)는 **논문 대조용 앵커**라 성격이 다르고,
논문 2.040 은 이미 도달 불가로 결론났으므로([감사 §2.5](2026-08-24_reproduction-audit.md)) 뒤로 미뤘다.

## 이 실험으로 확인하려는 것

미리 적어 둔다. 결과가 나온 뒤 아전인수식으로 읽는 것을 막기 위해서다.

1. **이 서버 Teacher 의 reduced ERGAS 값.** 이후 모든 축소 구성 비교의 분모다.
   원 서버 `wv3_fixed_valsel` 은 2.1804 였다. **같으면 좋지만 같을 필요는 없다** —
   다르면 그것이 서버 간 학습 변동의 크기이고, 그래서 기준선을 따로 잡는 것이다.
2. **수렴 곡선의 모양.** `metrics.csv` 로 상위 epoch 구간이 평탄한지 본다.
   원 서버에서는 상위 5개 epoch 폭이 0.18% 였다. 여기서도 평탄하면 best 선택이 안정적이다.
3. **학습 시간 실측.** 위 예상치가 맞는지. 이후 실험 계획의 비용 산정 근거가 된다.
