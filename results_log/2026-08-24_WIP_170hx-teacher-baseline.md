새 서버에 환경을 옮기고, [논문 충실 재구성본](2026-08-24_paper-faithful-rebuild.md)의
**50K 1벌 + 25K 1벌**을 이 서버에서 확보한다.

## 왜 이 두 벌인가

앞으로 student 탐색을 **25K** 로 진행하는데, 학습 수치는 서버 간 섞을 수 없다
(같은 설정 4벌 폭 0.79%). 따라서 이 서버에 두 좌표가 필요하다.

| 실행 | 역할 |
|---|---|
| `p25_s2025` (25K) | student 비교의 **대조군**. 모든 축소 구성이 이것과 대응표본으로 붙는다 |
| `paper_wv3` (50K) | **25K 가 얼마나 덜 수렴했는지의 보정 기준**. 배포 코드에서는 25K→50K 가 −3.6% 였다 |

둘 다 같은 GPU 라 내부 비교가 성립한다. 실행: `tools/_run_170hx.sh`

## 중단한 실행 — 배포 코드 앵커 (실패 사례로 남긴다)

처음에 `wv3_fixed_valsel`(배포 코드 9.969 M) 50K 를 이 서버 Teacher 기준선으로 걸었다.
**epoch 90/248, 2h20m, val ERGAS 2.3327 에서 중단했다.**

중단 이유는 그 사이 [재구성본 결과](2026-08-24_paper-faithful-rebuild.md)가 나왔기 때문이다.
배포 코드 기준선은 **배포 코드 기준 student 를 비교할 때만** 쓸모가 있는데, 경량화 축이
재구성본 기준으로 옮겨가면서 그 용도가 사라졌다. "동일 서버 대조군은 하나 있어야 한다"는
이유로 계속 돌릴 뻔했으나, 비교 대상이 없는 대조군은 대조군이 아니다.

**교훈**: 기준선을 먼저 잡는 습관이 항상 옳지는 않다. **무엇과 비교할 것인지가 확정된 뒤에**
기준선을 잡아야 GPU 시간을 버리지 않는다.

## VRAM — 재구성본 OOM 우려는 해소됐다

[재구성 문서 §6](2026-08-24_paper-faithful-rebuild.md)이 "3-scale 이라 고해상도 활성값이 커서
batch 48 에서 OOM 가능성" 을 한계로 적었다. **실효 배치 96 을 직접 올려 실측한 결과는 반대다.**

| batch 48 (MARs 복제 후 96) | peak allocated |
|---|---:|
| **논문 재구성본** | **15.38 GiB** |
| 배포 코드 | 16.65 GiB (KNOWN_ISSUES G 실측 16.51 과 0.8% 일치 — 측정 타당성 확인) |

**재구성본이 배포 코드보다 1.3 GiB 적게 쓴다.** 배포 코드가 이미 24GB 카드에서 도는 이상
재구성본도 batch 48 로 OOM 나지 않는다. 메모리를 먹는 것은 CM3A 의 ka²=9 확장인데
AttnBlock 이 5개에서 3개로 줄었기 때문이다.

## 이 실험으로 확인하려는 것

미리 적어 둔다. 결과가 나온 뒤 아전인수식으로 읽는 것을 막기 위해서다.

1. **`paper_wv3` 50K 의 reduced ERGAS.** 이것이 관문이다. 논문 2.040 근처(≲2.08)면
   "배포 코드가 논문 모델이 아니었다" 가 성립한다. 배포 코드 재현치 2.16~2.18 대에
   머물면 구조가 원인이 아니므로 student 탐색의 전제 자체를 다시 봐야 한다.
2. **25K 와 50K 의 격차.** 배포 코드에서는 −3.6% 였다. 재구성본에서도 비슷하면
   앞으로 25K 로 탐색한 결과를 50K 로 환산해 읽을 수 있다.
3. **수렴 곡선의 평탄도.** 상위 epoch 구간이 평탄해야 best 선택이 안정적이다.
   배포 코드에서는 상위 5개 epoch 폭이 0.18% 였다.

## 주의

- 이 서버 수치는 원 서버 수치(Teacher 2.1804 등)와 **한 표에 넣지 않는다.**
- **0.8% 미만의 차이는 시드 3개 이상**에서 방향이 일관될 때만 주장한다
  (`CLAUDE.md` 판정 규칙). 이 두 벌은 각각 단벌이므로, 이후 student 비교에서
  0.8% 미만 차이가 나오면 시드를 늘려야 한다.
- `test_full_feeder_args` 가 복구본이 아닌 원본 `full_examples_h5` 를 보는지
  체인 종료 후 확인한다. 손상된 `lpan`([F-1](../KNOWN_ISSUES.md))이면 학습 로그의
  full-res 지표는 무효다(`select_on: val` 이라 선택에는 쓰이지 않는다).
