# 2026-08-24 — 논문 충실 재구성 + 재현 감사 + WV3 프로토콜 정의

이 날의 네 문건(결과 3 + WIP 1)을 하나로 합쳤다. **재현 축이 여기서 결론에 도달한다.**

| 갈래 | 결론 |
|---|---|
| **논문 충실 재구성** | 논문 서술대로 다시 구현하니 **params 가 7.1707 M 으로 논문 주장 7.170 M 과 +0.01% 일치**(배포 코드 9.969 M). 되돌린 것 셋 다 논문 본문 — mode modulation 을 Eq (6) 직접 학습 γ,β 로 · bottleneck 도 k=3 · 입력 9ch. **FLOPs 79.03 G 는 미해결**(재구성본 161.9 G, 어텐션 빼도 125.9 G — '미집계' 가설 기각) |
| **재현 감사** | ① **우리 수정은 무죄** — 기본값이 배포 원본과 **비트 동일**(출력 diff 0) ② **논문 격차도 측정 무죄** — CANConv 배포 가중치로 논문 행을 **6지표 0.5% 이내** 재현 → **배포 코드 ≠ 논문 모델**이 유력 ③ **논문의 CANConv 대비 우위는 재현되지 않는다**(주장 −5.69% vs 재현 −0.34%, p=0.667) |
| **WV3 프로토콜 정의** | `baseline`(배포본 그대로) vs `fixed`(논문 Eq 10/11·Sec 3.3 복원)의 정의와 왜 둘 다 돌리는지. **25K·50K 를 가로로 읽으면 안 된다**(편향 −3.6%) |

기준선이 9.969 M → 7.171 M 로 바뀌면서 **'−33% 무손실'의 상당 부분은 배포본 잉여**였음이
드러났고, 경량화 축도 **width ≫ full-res depth** 로 이동했다.

> **후속 정정**: 여기서 얻은 "시드 폭 0.81%"(ERGAS)는 이 시점 구성의 값이다.
> **HQNR 판정 밴드는 이후 무효 판정**됐다 ([2026-09-04](2026-09-04_placement-and-band-invalidation.md)).

## 논문 충실 재구성 — 무엇이 달라졌고 어디를 줄일 것인가 (2026-08-24)

> 원문: `2026-08-24_paper-faithful-rebuild.md`

### 결론

**논문이 기술한 대로 다시 구현했더니 파라미터가 정확히 맞았다.**

| | 논문 주장 | 배포 코드 | **논문 충실 재구성** |
|---|---:|---:|---:|
| Params | **7.170 M** | 9.969 M (+39.0%) | **7.1707 M (+0.01%)** |
| FLOPs | 79.03 G | 168.1 G (+112.7%) | 161.9 G (+104.9%) |
| spatial scale | — | 4 | **3** |
| Down/UpConv | — | 3 / 3 | **2 / 2** |
| AttnBlock | — | 5 | **3** |
| ResBlock | — | 14 | **12** |

**파라미터는 완전히 설명됐고, FLOPs 는 여전히 설명되지 않는다.**

새 구현은 `model/pancrafter_paper.py`, 설정은 `config/paper_wv3.yaml` 이다.
WV3 50K 학습을 우선순위로 큐에 걸었다(`tools/_run_priority.sh`).

### 1. 무엇을 바꿨나 — 셋 다 논문 본문에 있다

파라미터가 맞은 것은 임의 조합의 결과가 아니다. **논문이 명시한 세 가지를 되돌렸더니**
7.17 M 이 나왔고, 셋 중 하나라도 배포 코드 쪽으로 되돌리면 일치가 사라진다.

#### (1) mode modulation — 가장 큰 몫

| | |
|---|---|
| **논문 Eq (6)** | *"γ_ms, β_ms, γ_pan, β_pan ∈ R^C are learnable parameters"* |
| **배포 코드** | mode token 을 블록마다 `Linear(128, 2C)` 로 사영 — **블록당 33,024** params |
| **재구성** | mode 별 γ, β 를 직접 학습 — **블록당 512** params |

블록당 **32,512** 씩, ResBlock 12 + AttnBlock 3 = 15 블록에서 **약 0.49 M** 차이다.

#### (2) local attention kernel — bottleneck 만 달랐다

논문은 *"we empirically set ... the local attention kernel size to k = 3"* 이라고 전역으로 쓴다.
배포 코드는 bottleneck 만 `_attn(3, **1, 1**)` 로 k=1 이다(AttnBlock 285,344 vs 969,376).
재구성은 전 위치 k=3 이다.

#### (3) 입력 구성

| | |
|---|---|
| **논문** | *"Pθ takes as input the channel-wise concatenation of I_pan and I_lrms"* → **9 ch** |
| **배포 코드** | `PAN, ↑LPAN, PAN−↑LPAN, ↑MS` → **11 ch** |

#### 그리고 구조 자체 (Figure 3)

Figure 3 은 **spatial scale 3, DownConv 2, UpConv 2, AttnBlock 3** 이다. 배포 코드는 4/3/3/5 다.
본문도 *"low- and mid-resolution stages incorporate both ResBlock and AttnBlock, while
**high-resolution stages use only ResBlock** to reduce computational overhead"* 라고 쓴다.
4단계를 high/mid/low 로 나누면 H/2 는 high 이므로 **H/2 에 CM3A 가 있으면 안 된다.**
배포 코드는 H/2 encoder·decoder 양쪽에 둔다.

재구성의 배치는 다음과 같다.

```
full-res : ResBlock only          (high)
   v Down
H/2      : ResBlock + AttnBlock   (mid)
   v Down
H/4      : ResBlock + AttnBlock   (low, bottleneck)
   ^ Up
H/2      : ResBlock + AttnBlock   (mid)
   ^ Up
full-res : ResBlock only
```

#### 함께 적용한 것 (KNOWN_ISSUES A-1 / A-2)

재구성본은 논문 수식이 기준이므로 `fix_key_alias`·`fix_local_attn` 을 **켠 상태**다 —
CM3A 의 key 별칭을 Eq (10)/(11) 대로 고치고, `dep_conv` 를 Sec 3.3 의 shift kernel 로 고정했다.

### 2. 여전히 설명되지 않는 것 — FLOPs

**재구성본의 FLOPs 는 161.9 G 로, 논문 79.03 G 의 2.05 배다.** 파라미터가 +0.01% 로 맞은 것과 대조된다.

한때 "어텐션이 집계되지 않았을 것" 이라는 가설을 세웠다. 배포 구조에서 CM3A 를 빼고 depth 를
낮춘 조합이 **79.2 G** 로 79.03 과 +0.2% 안에 들었기 때문이다. **그러나 이 가설은 기각한다** —
재구성본에서 AttnBlock 을 전부 빼도 **125.9 G** 로 79 G 에 닿지 않는다. 79 G 는 서로 무관한
여러 구성이 우연히 지나가는 값이고, 한 번 맞았다는 것만으로는 근거가 되지 않는다.

| 구성 | FLOPs | vs 79.03 |
|---|---:|---:|
| 재구성본 (AttnBlock 3) | 161.9 G | +104.9% |
| 재구성본 (AttnBlock 0) | 125.9 G | +59.3% |
| 배포 구조, CM3A 0 + D1121 | 79.2 G | +0.2% ← **우연** |

논문은 FLOPs 측정 도구도 MACs/FLOPs 규약도 명시하지 않고, ablation 표에 params·FLOPs 열이
없어 내부 대조도 불가능하다. **저자 코드 없이는 여기까지가 한계다.**

> 참고로 **논문의 파라미터 계수 방법 자체는 정확하다.** Table 10 의 CANConv 행 0.79 M 은
> 배포 가중치 실측 0.787 M 과 0.4% 안에서 맞는다. 즉 7.17 M 도 계수 오류가 아니라
> **다른 모델의 수치**이고, 그 모델이 이 재구성본이라는 것이 §1 의 결론이다.

### 3. 지금까지의 실험과 무엇이 달라지나

#### 3.1 기준선이 바뀐다

지금까지 모든 프루닝 실험은 **배포 코드(9.969 M)** 를 Teacher 로 삼았다.
재구성본이 논문 모델이라면, **비교 기준은 7.17 M 이어야 한다.**

| | 배포 코드 기준 (기존) | 재구성본 기준 (앞으로) |
|---|---|---|
| Teacher | 9.969 M / 168.1 G / 17.4 ms | 7.171 M / 161.9 G / (측정 예정) |
| 선정 Student 6.694 M 의 의미 | Teacher 대비 **−33%** | Teacher 대비 **−6.7%** |

**즉 "파라미터 33% 무손실 감축" 이라는 기존 결론의 상당 부분이,
배포 코드에만 있던 잉여를 걷어낸 것이었다.** 우리가 제거해 무손실이었던 것들
(H/2 CM3A 2개, PAN K/V 브랜치)이 애초에 논문 모델에 없던 것이라면 자연스러운 결과다.

이는 [8/21 ablation](2026-08-21_submodule-ablation.md) 의 "모든 서브모듈이 개별로 +1.5% 이내
제거 가능" 과 [8/22 확장 실험](2026-08-22_extended-ablation-and-kd-target.md) 의 "6.694 M 이
Teacher 와 구분 불가" 를 **뒤집지는 않는다.** 다만 **그 감축의 기준점이 부풀려져 있었다**는 뜻이다.

#### 3.2 시드 변동이 대부분의 차이를 삼킨다

시드 반복 결과가 나왔다. **동일 구성**(`x1_panbr_dec4`)을 시드만 바꿔 돌린 것이다.

| 실행 | seed | ERGAS |
|---|---:|---:|
| `x1_panbr_dec4` | 2025 | 2.2527 |
| `z_seed1234` | 1234 | **2.2344** |
| `z_seed7777` | 7777 | (학습 중) |

**시드 2개만으로 폭이 0.81%** 다. 지금까지 인용해온 차이들과 비교하면:

| 비교 | 차이 | 시드 폭 대비 |
|---|---:|---|
| 선정 Student vs Teacher | −0.31% (p=0.114) | **시드 폭의 0.4배** |
| 6.041 M vs 6.694 M | +0.74% (p=0.013) | **시드 폭의 0.9배** |
| A-1/A-2 적용 효과 | +0.74% (p=0.0014) | **시드 폭의 0.9배** |

**대응표본 t-검정은 같은 가중치를 20장에 적용한 것이라 시드 변동을 포착하지 못한다.**
p 값이 작아도 시드를 바꾸면 뒤집힐 수 있다는 뜻이다.

> **앞으로의 판정 기준.** 구조 차이를 주장하려면 **시드 3개 이상**에서 방향이 일관되어야 한다.
> 단일 시드 대응표본 p 값만으로는 0.8% 미만의 차이를 주장하지 않는다.

#### 3.3 논문 격차 진단의 우선순위가 내려간다

`d1_nocrop`(증강 scale jitter)·`d2_lmsbase`(잔차 기준선)는 ERGAS 6% 격차의 원인 후보였다.
그런데 **구조 자체가 다르다는 것이 확인됐으므로**, 이 둘의 설명력은 부차적이다.
우선순위 체인에서 재구성본 뒤로 미뤘다(제거하지는 않았다 — 학습 파이프라인 자체의 문제라면
재구성본에도 똑같이 걸리므로 여전히 확인 가치가 있다).

### 4. 재구성본 기준 경량화 전략

`256×256×8` 출력 기준 실측이다. 기준: **7.1707 M / 161.9 G**.

| 손잡이 | Params | ΔP | FLOPs | ΔF | 평가 |
|---|---:|---:|---:|---:|---|
| **width 128 → 96** | 4.060 | **−43.4%** | 91.8 | **−43.3%** | 유일하게 둘 다 크게 준다 |
| AttnBlock 전부 제거 | 4.362 | −39.2% | 125.9 | −22.2% | 방법의 핵심을 버리는 것 |
| AttnBlock 2개 제거 (H/2 양쪽) | 5.298 | −26.1% | 141.9 | −12.3% | params 는 크게, FLOPs 는 적게 |
| AttnBlock 1개 제거 (H/2 decoder) | 6.234 | −13.1% | 145.9 | −9.9% | |
| **full-res depth 2→1** | 6.578 | −8.3% | **123.2** | **−23.9%** | **FLOPs 효율 최고** |
| H/2 depth 2→1 | 6.578 | −8.3% | 152.2 | −6.0% | |
| bottleneck depth 4→2 | 6.578 | −8.3% | 159.4 | −1.5% | params 만 준다 |
| mlp_ratio 4→2 | 6.973 | −2.8% | 159.4 | −1.5% | 미미 |

#### 배포 코드 때와 무엇이 다른가

**배포 코드에서는 "CM3A 를 빼면 공짜" 였지만, 재구성본에서는 그 여지가 이미 없다.**
논문 모델은 AttnBlock 이 3개뿐이고 전부 mid/low 해상도에 있다. 배포 코드에서 무손실로
제거했던 H/2 CM3A 2개와 PAN K/V 브랜치는 **애초에 여기 없다.**

따라서 축이 바뀐다.

```
배포 코드 :  CM3A 개수 -> PAN 브랜치 -> depth -> width
재구성본  :  width  >>  full-res depth  >  AttnBlock 개수  >  나머지
```

#### 권장 순서

| | 실험 | 근거 | 예상 |
|---|---|---|---|
| **1** | **재구성본 50K 기준선 확보** | 모든 비교의 출발점. 논문 2.040 에 얼마나 근접하는지가 이 재구성의 타당성 검증이다 | 진행 중 |
| **2** | **full-res depth 2→1** | FLOPs −23.9% 를 params −8.3% 로 산다. **FLOPs 효율이 가장 좋은 단일 손잡이** | 6h |
| **3** | **width 128→96** | 둘 다 −43%. 다만 배포 코드 스윕에서 width 축소는 ERGAS 손해가 컸다(128→96 에서 +7.7%). **재구성본에서도 같은지 확인이 필요하다** | 6h |
| 4 | AttnBlock 1개 제거 (H/2 decoder) | params −13% / FLOPs −9.9%. 배포 코드에서 decoder 쪽 제거가 가장 안전했다 | 6h |
| 5 | bottleneck depth 4→2 | params −8.3% 를 FLOPs −1.5% 로. **bottleneck 은 싸므로 오히려 늘릴 후보** | 6h |

#### 주의

- **width 축은 배포 코드에서 가성비가 최악이었다** (128→96 에 ERGAS +7.7%, 속도 이득 미미).
  재구성본은 3-scale 이라 고해상도 비중이 더 크므로 **결과가 다를 수 있다.** 3번을 건너뛰지 말 것.
- **bottleneck 을 줄이는 것은 마지막이다.** FLOPs 기여가 1.5% 뿐이라 줄여도 안 빨라진다.
  반대로 **성능이 필요하면 여기를 늘리는 것이 가장 싸다.**
- **모든 비교는 시드 3개 이상**(§3.2). 재구성본 기준선부터 시드 반복을 계획에 넣어야 한다.

### 5. 미확정 — ResBlock depth

논문은 **stage 별 ResBlock 반복 수를 기재하지 않는다.** 파라미터 7.17 M 이라는 제약에서
**총 12개**라는 것까지만 정해지고, 배분은 특정되지 않는다.

`(2,2,4)`, `(1,3,4)`, `(3,2,2)`, `(1,1,8)` … 전부 **동일하게 7.1707 M** 이다.
현재 config 는 `(2,2,4)` 를 쓴다 — 배포 코드의 균등 depth 2 를 유지하되, 남는 2개를
**FLOPs 기여가 가장 작은 bottleneck**(1.5%)에 넣는 것이 "computational overhead 를 줄인다" 는
논문 서술과 가장 잘 맞기 때문이다.

**이 선택은 근거가 약하다.** 기준선이 나온 뒤 `(1,3,4)`(고해상도 최소) 와
`(3,2,2)`(고해상도 강화)를 함께 돌려 비교할 것을 권한다. FLOPs 가 크게 달라진다 —
`(1,2,4)` 는 123.2 G 인 반면 `(2,2,4)` 는 161.9 G 다.

### 6. 한계

- **재구성본의 성능은 아직 없다.** 이 문서의 주장은 전부 구조·파라미터 대조이고,
  ERGAS 등 품질 지표는 50K 학습이 끝나야 나온다. **재구성이 논문 수치(2.040)에
  근접하지 못하면 §1 의 결론도 재검토해야 한다.**
- **FLOPs 79.03 G 는 미해결**(§2).
- **depth 배분 미확정**(§5).
- 재구성본은 3-scale 이라 고해상도 활성값이 커서, **batch 48 에서 OOM 가능성**이 있다.
  학습 시작 시 확인이 필요하다.
- 시드 반복이 아직 2개다(3번째 학습 중).

| **그러면 왜 논문(2.040)보다 6% 나쁜가?** | 측정도 결백하고(논문 CANConv 행을 **6지표 0.5% 이내** 재현) 설정도 일치한다(**시드 2,025 포함**). 남은 설명은 **배포 코드가 논문의 모델이 아니라는 것**(params 1.39×, FLOPs 2.1×) |

그 귀결로 **논문이 주장하는 CANConv 대비 우위(−5.69%)가 재현되지 않는다** — 동일 평가기·동일 20장
대응표본에서 −0.34%, p=0.667, 10/20 승. 동전 던지기다.

> 이 문서는 8/24 에 따로 쓴 `paper-gap-analysis` 와 `multi-metric-review` 를 하나로 합치고,
> 수정 영향 감사(§1)를 새로 넣은 것이다. 8/22 문서에 절로 덧붙였던 내용을
> `CONVENTION.md` §5 에 맞게 분리한 결과이기도 하다. 수치는 그대로다.

### 1. 우리가 바꾼 것이 재현에 영향을 줬는가 — 아니다

재현은 **수정본 1벌 / 수정 이전 1벌**로 나눠 돌렸다. 그중 논문과 대조하는 수치는
`wv3_baseline`(수정 이전) 이다. 그것이 정말 배포본과 같은지 확인했다.

#### 1.1 모델 코드 — 기본값이 배포 원본과 **비트 동일**

`git show HEAD:model/pancrafter.py` 로 **저자 배포 원본을 꺼내** 현재 파일의 기본값 인스턴스와
직접 맞댔다.

| 항목 | 결과 |
|---|---|
| 파라미터 이름 집합 | 동일 (195개) |
| 파라미터 총 수 | 2,060,504 = 2,060,504 |
| 초기 가중치 최대 차이 | **0.000e+00** |
| 출력 최대 \|diff\| — PAN mode(s=0) / MS mode(s=1) / 혼합 | **0.000e+00 / 0.000e+00 / 0.000e+00** |

> **`zero_module` 함정 주의.** 이 모델은 초기 출력이 정확히 0 이라, 그냥 비교하면
> 어떤 코드를 넣어도 "동일" 이 나온다. 위 검증은 **0 인 파라미터 195개를 전부 난수로 채운 뒤**
> 비교한 것이다(비영 파라미터 195/195). 이 함정 때문에 초기 검증을 한 번 헛돌았다.

#### 1.2 학습·평가 쪽 변경 전수 점검

| 변경 | 재현 수치에 영향 | 확인 방법 |
|---|---|---|
| **A-1 / A-2** (모델) | **끄면 없음** — `wv3_baseline` 이 그 상태 | §1.1 |
| **C-1** `prepare(model, optimizer, scheduler)` | **없음** | 60 step 직접 학습 비교: 가중치 최대 \|diff\| **0.000e+00**, LR 스케줄 완전 동일. `mixed_precision=None` 이라 GradScaler 가 없고 `num_processes=1` 이라 스케줄러 배수도 1 |
| **C-4** `--res` 를 `str2bool` 로 | **없음** | config 가 `res: True` 라 버그 상태(`type=bool`)에서도 True |
| **C-2 / C-3** | 없음 | `save_epoch` 가드와 빈 로그 재출력 방지. 학습 경로 밖 |
| **D-2** ERGAS 정규화 | **best 선택에만, 0.1% 미만** | 아래 |
| **D-1 / D-3~D-6** | 없음 | 로그 라벨·CSV·import 정리 |
| **E-1** `select_on` | 선택 규칙만 (val 일 때) | test-sel → val-sel 로 바꿔도 **+0.05%** (baseline, p=0.65) |

**D-2 가 왜 무시 가능한가.** best 체크포인트는 `ERGAS` 로 고르는데(`main.py`),
그 ERGAS 가 D-2 로 바뀐 함수다. 즉 `wv3_baseline` 도 *선택* 단계에서는 수정된 지표를 썼다.
영향 크기를 세 방향으로 눌러봤다.

- 두 정의의 값 차이는 수렴한 모델에서 **0.2%** (2.1530 vs 2.1487).
- 수렴 구간이 평탄하다 — 상위 5개 epoch 의 ERGAS 폭 **0.18%**, 마지막 10 epoch 폭 **0.01%**.
- 선택 규칙 자체를 통째로 바꿔도(E-1: 테스트셋 → 검증셋) 최종 수치는 **+0.05%** 밖에 안 움직인다.

**어느 쪽으로 재도 0.1% 미만이다. 6.09% 격차의 1/60 이하라 설명이 되지 않는다.**

#### 1.3 다만 A-1/A-2 **자체**는 유의한 영향이 있다

수정본과 수정 이전을 선택 규칙 고정하고 대응표본으로 비교했다 (50K, WV3, DLPan).

|---|---|---:|---:|---:|---:|---|
| test-sel | ERGAS↓ | **2.1633** | 2.1765 | **+0.61% 악화** | 0.0057 | 유의 (수정본 승 4/20) |
| val-sel | ERGAS↓ | **2.1643** | 2.1804 | **+0.74% 악화** | 0.0014 | 유의 (수정본 승 1/20) |

> 이것은 [8/19 보고서](2026-08-19_metric-audit-and-wv3-four-runs.md)의 "in-domain 중립~손해,
> WV2 zero-shot 에서 HQNR +2.0%" 와 같은 결론이며, 여기서 유의성까지 확정했다.

#### 1.4 주의 — 프루닝 실험 43벌은 전부 **수정본** 계열이다

| 계열 | 실행 수 |
|---|---:|
| `fix_key_alias=False, fix_local_attn=False` (배포본) | **2** (`wv3_baseline`, `wv3_baseline_valsel`) |
| `fix_key_alias=True, fix_local_attn=True` (수정본) | **43** (스윕·ablation·조합·2축 전부) |

- **논문 대조는 문제없다.** §2 의 2.1633 은 배포본 2벌 중 하나다.
- **프루닝 결론도 내부적으로는 정합적이다.** 43벌이 모두 같은 조건이라 상대 비교가 성립한다.
  이들의 기준 Teacher 는 2.1804(50K) / 2.2598(25K) 이다.
- **다만 최종 산출물을 배포본과 나란히 놓으려면 기준선이 0.7% 어긋난다.**
  권장 구성(`x1_panbr_dec4`, 6.694M)을 `fix_*: False` 로 50K 한 벌 더 돌리면 정리된다.
  추론이 2.2배 빠르므로 **약 2.5시간**이면 된다. 진단 체인(21:10) 뒤에 붙일 수 있다.

#### 2.5 남은 후보

| # | 후보 | 증거 | 상태 |
|---|---|---|---|
| **A** | **배포 코드 ≠ 논문 모델** | params 9,968,808 vs 주장 7.17 M (**1.39×**, 계수값이라 해석 여지 없음). FLOPs 168.1 G(thop) / 158.3 G(fvcore) vs 79.03 G (**2.0~2.1×**, 독립 두 도구가 6% 이내 일치) | **가장 유력** |
| B | 증강 `crop` 이 실은 scale jitter | 자른 뒤 `cv2.resize` 로 원크기 복원 → `ms` 와 `gt` 가 각각 bicubic 리샘플되어 **MS→GT 열화관계(MTF+decimation)가 깨진다.** 테스트엔 그 왜곡이 없다 | **검증 중** |
| C | 잔차 기준선 `bicubic(ms,×4)` | 데이터셋 `lms` 대신 사용. 단독 기준선 ERGAS 7.3035 vs 7.1220(**2.5% 나쁨**), 평균 \|diff\| 10.684 (0–2047 기준 3.28%) | **검증 중** |

**왜 A 가 유력한가.** 파라미터 수는 해석 여지 없는 계수값인데 39% 어긋나고, FLOPs 는 독립 두 도구가
일치하는데 2.1배 어긋난다. 그리고 **서브모듈을 어떻게 조합해 빼도 논문 수치에 닿지 않는다** —
CM3A 를 전부 제거해도 5.806 M / 127.8 G 로 FLOPs 는 여전히 주장보다 62% 높다.

즉 **배포된 코드는 논문 Table 10 을 만든 모델이 아니다.** 그 코드로 학습한 가중치가
Table 3 의 2.040 을 내지 못하는 것은 자연스러운 귀결이다. 이는
[8/21 ablation](2026-08-21_submodule-ablation.md) 과도 맞물린다 — PAN 브랜치를 통째로 빼도 +1.07%,
오히려 나아지는 구성도 있었다. **배포본에 논문 최종 모델에는 없던 부분이 남아 있고, 그것이
파라미터를 부풀리면서 성능에는 기여하지 않는다**는 그림이 일관된다.

#### 3.1 핵심 구성의 지표별 유의성 (Teacher 대비, 대응표본)

|---|---:|---|---|---|---|---|
| −PAN브랜치 (CM3A 5) | 8.65 M | +0.44% (0.137) | +0.02% (0.939) | +0.02% (0.784) | **+13.80%*** | **+1.32%*** |

| **−H/2 −PAN −decH/4** | **6.69 M** | +0.32% (0.114) | −0.15% (0.416) | +0.04% (0.655) | **+32.33%*** | **+3.20%*** |

**`6.69 M` 은 reduced 3종이 모두 Teacher 와 구분되지 않고 full-res 2종은 유의하게 좋다.**
어느 지표도 유의하게 나빠지지 않는다. **`6.04 M` 에서 처음 실제 비용이 나타난다** —
ERGAS·SAM 이 유의하게 악화(p=0.013 / 0.001). CM3A 를 2개에서 1개로 줄이는 지점이 경계다.

#### 3.2 D_s 가 축소할수록 좋아지는 이유

착시가 아니라 기전이 있다. D_s 는 "PS 밴드와 PAN 의 관계" 가 "MS 와 저역통과 PAN 의 관계" 에서
얼마나 벗어났는지를 잰다. **PAN 고주파를 덜 주입할수록 낮아진다.** CM3A·PAN 브랜치를 줄이면
PAN 주입이 줄어드니 D_s 가 좋아지는 것이 당연하다.

**다만 이것만으로 "축소가 더 낫다" 고 읽으면 안 된다.** D_s 는 "아무것도 주입하지 않기" 를 최적해로
보는 성질이 있다([8/14 보고서](2026-08-14_wv3-baseline-vs-fixed.md)에서 `best_full` 이 epoch 5 를
고른 것과 같은 이유다 — 실제로 그 체크포인트의 ERGAS 는 2.86 으로 크게 나쁘다).
**의미 있는 조합은 "ERGAS·SAM 이 유지되면서 D_s 가 좋아지는 것"** 이고 `6.69 M` 이 정확히 거기다.
반대로 `6.04 M` 은 ERGAS·SAM 이 유의하게 나빠지면서 D_s 개선도 유의하지 않다 — 그냥 나빠진 것이다.

#### 3.3 8/22 결론에 대한 영향

- **강화됨**: `6.69 M` 은 5개 지표 중 3개 무차별, 2개 유의 개선. ERGAS 단독보다 근거가 강하다.
- **강화됨**: PAN 브랜치 제거는 CM3A 5개 기준에서 **9개 지표 전부** Teacher 이상.
- **약화되지 않음**: `6.04 M` 의 +0.42% 는 ERGAS·SAM 양쪽에서 유의하므로 실재하는 손실이다.
- **주의**: Q8·SSIM·SCC 는 포화 상태라 **판별 근거로 인용하면 안 된다.** 논문 Table 이 Q8 을
  주요 지표로 쓰지만 우리 축소 범위에서는 변별력이 없다.

### 6. 이 결과가 연구에 갖는 의미

1. **비교 기준은 재현 Teacher 여야 한다.** 논문 2.040 은 우리가 가진 코드로 도달 불가능하고,
   그것이 우리 쪽 결함이 아님을 §1·§2 에서 확정했다. 프루닝·KD 의 이득은 재현 Teacher 대비로 잰다.
2. **효율 여지가 오히려 커진다.** 배포본에 기여 없는 부분이 남아 있다는 가설은, 권장 구성
   **6.694 M(−33%) / 8.3 ms(2.2×) 가 Teacher 와 구분 불가**(p=0.114)라는 실측과 같은 이야기다.
   이 구성은 **논문이 주장하는 7.17 M 보다도 작다.**
3. **KD 의 목표선이 분명해진다.** Teacher 자신이 CANConv 급이므로 KD 가 메워야 할 것은
   "논문 대비 6%" 가 아니라 **"6 M 아래로 내려갈 때 생기는 실제 하락"** 이다.
4. **논문 대비 우위 주장은 인용하지 않는다.** 재현되지 않는 수치를 베이스라인으로 쓰면
   우리 결과도 같이 무너진다.
5. **최종 산출물은 배포본 기준으로 한 벌 더 돌린다** (§1.4, 약 2.5h).

### 1. 프로토콜 정의

#### 1.1 두 실행 계열 — `baseline` 과 `fixed`

배포 코드에는 **논문 수식과 다르게 동작하는 두 곳**이 있다. 어느 쪽이 옳은지 단정하지 않고
**토글로 분리해 양쪽을 다 돌렸다.** 기본값은 배포본 동작이다.

| 계열 | 정의 |
|---|---|
| **`baseline`** | 배포 코드를 **고치지 않은 상태**. `fix_key_alias=False`, `fix_local_attn=False` |
| **`fixed`** | 아래 A-1·A-2 를 **논문 수식대로 되돌린 상태**. 둘 다 `True` |

##### A-1 — CM3A 의 key 변수가 덮어써진다

`model/pancrafter.py`, 배포 원본:

```python
q, k_pan, k_pan = self.q_norm(...), self.k_norm_pan(k_pan...), self.k_norm_ms(k_ms...)
#     ^^^^^  ^^^^^  좌변에 k_pan 이 두 번, k_ms 가 없다
```

튜플 좌변이 `(q, k_pan, k_pan)` 이라 세 번째 값이 두 번째를 덮는다. 두 가지가 함께 깨진다.

1. `self.k_pan` conv 출력이 통째로 버려지고 **PAN 브랜치가 MS key 로 attention 을 계산**한다.
2. `k_ms` 는 재할당된 적이 없어 다음 줄 `permute` 왕복이 성립하지 않는다.
   원소 수가 같아 **예외 없이 통과**하면서 내용만 뒤섞인다.

논문 **Eq (10)/(11)** 의 `x_pan = LocalAttn(Q, K_pan, V_pan)`,
`x_ms = LocalAttn(Q, K_ms, V_ms)` 와 어긋난다.

실측: `k_pan(실제) == k_ms conv 출력` → True. `grad=None` 파라미터 10개 / **611,584 개**
(전체의 6.13%)가 죽어 있다. `value` 는 정상이라 cross-modality 정보 자체는 흐르므로,
망가진 것은 aggregation weight 를 만드는 key 쪽뿐이고 학습은 그대로 진행된다.

**`fixed` 는 좌변만 `q, k_pan, k_ms` 로 고친다.** `qk_norm=False` 라 세 norm 은 모두
`Identity` 이므로 실질 효과는 (a) 죽어 있던 6.13% 가 살아나고 (b) `k_ms` 가 뒤섞이지 않는 것뿐이다.

##### A-2 — `reset_parameters()` 가 한 번도 호출되지 않는다

`dep_conv` 를 one-hot shift kernel 로 채우고 `requires_grad=False` 로 고정하는 함수인데,
**저장소 전체에 호출부가 없다**(정의 1건뿐). 이 초기화가 있어야 `dep_conv` 가 k×k 이웃을
그대로 모아오는 연산이 되어 논문 **Sec 3.3** 의 *"LocalAttn computes attention scores within
the k × k local receptive field"* (ACmix 방식)가 성립한다.

실측: `requires_grad=True`, weight 가 0/1 shift kernel 이 아니며, **학습되는 `dep_conv`
파라미터 7,200 개**. 3×3 수용영역은 유지되지만 softmax 가 고르는 9개 후보가
"3×3 이웃 9픽셀" 이 아니라 **"3×3 패치의 학습된 선형결합 9개"** 다.

**`fixed` 는 `reset_parameters()` 를 호출하고, bias 도 0 으로 고정한다** —
weight 만 고정하면 모아온 이웃값에 상수 offset 이 더해져 순수한 gather 가 되지 않는다.

##### 이 구분이 필요한 이유

**A-1/A-2 는 성능에 유의한 영향을 준다.** 선택 규칙을 고정하고 대응표본으로 비교했다(50K).

| 지표 | `baseline` | `fixed` | 차이 | p |
|---|---:|---:|---:|---:|
| ERGAS↓ | **2.1643** | 2.1804 | +0.74% 악화 | **0.0014** |
| SAM↓ | 2.9123 | **2.9024** | −0.34% 개선 | **0.0202** |

**논문 수식대로 고치면 ERGAS 는 나빠지고 SAM 은 좋아진다.** 두 선택 규칙(test-sel / val-sel)에서
방향이 일관되므로 실재하는 효과다. 어느 쪽이 "옳은" 재현인지 수치만으로는 정할 수 없어
**두 계열을 병기한다.** 논문 Table 과 대조할 때는 `baseline`(배포 코드 그대로)을 쓴다.

> **모든 수치에 계열을 표기한다.** 이것을 빠뜨리면 "재현 실패" 와 "코드 수정 효과" 를
> 구분할 수 없다 (`CONVENTION.md`).

#### 1.2 왜 50K 가 아니라 25K 인가

논문과 배포 config 모두 **50,000 iteration** 이다. 재현 실행은 50K 로 했고,
**구조 탐색 실험만 25K(50%)로 줄였다.**

**이유는 예산이다.** WV3 50K 는 실측 **5.94시간**이다.

| | 50K 로 전부 | 25K 로 전부 |
|---|---:|---:|
| 구조 스윕 12종 | 약 71h | **15h 08분** (실측) |
| 서브모듈 ablation 8종 + 조합 9종 | 약 100h | 29h (실측) |
| 확장 8종 | 약 47h | 15h (실측) |

50K 로는 하루에 4종밖에 못 돈다. **구조 비교는 순위 판정이 목적이므로 절대값 손해를
받아들이고 표본 수를 택했다.**

**25K 의 대가를 먼저 분리했다.** 동일 구성(`fixed`, W128 D2222 CM3A5)을 두 길이로 돌려 비교했다.

| | 25K | 50K | 차이 |
|---|---:|---:|---|
| ERGAS↓ | 2.2598 | 2.1804 | **−3.6%** |

즉 **25K 값은 일관되게 3.6% 비관적**이다. 이 편향은 모든 25K 구성에 같은 방향으로 걸리므로
**구성 간 상대 비교는 유효**하고, **절대값을 논문·50K 와 같은 표에 놓으면 안 된다.**

한 가지 유의점: 작은 모델이 더 빨리 수렴할 수 있어 25K 비교는 **소형 구성에 다소 유리**하다.
그래서 확정 후보는 50K 로 재확인한다 — 실제로 격차가 절반으로 줄었다(+0.88% → +0.41%).

`256×256×8` 출력, 배치 1, RTX 4090 실측. 학습시간은 WV3 실측이다.

차이는 학습 파라미터 **7,200 개**(A-2 가 `dep_conv` 를 고정)뿐이며, 추론 비용에는 영향이 없다.

**세 비용 지표가 서로 다른 이야기를 한다.** 선정 Student 는 파라미터 −33%인데 FLOPs 는
−22%(168.1 → 130.7)뿐이고 **시간은 2.1배** 빨라진다. 제거한 CM3A 가 저해상도(H/2·H/4)
블록이라 파라미터 비중은 크지만 연산량 비중은 작고, 어텐션은 메모리 대역폭에 묶여
FLOPs 보다 실측 시간에 더 크게 기여하기 때문이다. **하나만 인용하면 오독된다.**

### 3. 읽는 법

#### 3.1 Student 는 자기 Teacher 를 이긴다

25K 그룹 안에서 보면 선정 Student(2.2527)가 Teacher(2.2598)보다 **낮다**(−0.31%, p=0.114).
50K 재현본(2.1643)이 더 낮은 것은 **학습을 2배 했기 때문**이고 구조 차이가 아니다 —
동일 구성을 25K→50K 로 늘리면 3.6% 개선된다(§1.2).

이를 직접 확인한 대조군이 있다. **최대 감축 구성**(`x3_maxcut_50k`, CM3A 를 H/4 encoder 하나만
남긴 것으로 선정 Student 보다 더 공격적)을 50K 로 돌리면 **2.1894** 다. 50K 끼리 비교하면
격차가 2.1643 → 2.1894, 즉 **1.16%** 로 줄어든다 — 25K 에서 보이던 4.1% 의 대부분이
iteration 이었다는 뜻이다.

#### 3.2 판별력이 있는 지표는 ERGAS·SAM 뿐이다

25K 네 행에서 Q8 은 0.9133–0.9138, SSIM 은 0.9733–0.9736 — 폭이 **0.05% 이내로 포화**다.
**Q8·SSIM·SCC 를 판별 근거로 인용하면 안 된다.** 논문 Table 은 Q8 을 주요 지표로 쓰지만
우리 축소 범위에서는 변별력이 없다.

D_s·HQNR 은 축소하면 거의 항상 좋아지는 **기전**이 있다 — D_s 는 PAN 고주파를 덜 주입할수록
낮아지므로, CM3A·PAN 브랜치를 줄이면 개선되는 것이 당연하다. `best_full`(D_s 기준) 체크포인트가
epoch 5 를 골라 ERGAS 2.86 이 나오는 것과 같은 이유다. **단독 해석 금지**이고,
의미 있는 조합은 "ERGAS·SAM 이 유지되면서 D_s 가 좋아지는 것" 이다.

#### 3.3 아직 확정할 수 없는 것

이 표의 25K 행 간 차이는 **0.3–0.7%** 다. 그런데 **시드 변동 폭을 아직 모른다.**
같은 설정 50K 4벌의 폭이 이미 **0.79%** 였다. 시드 반복 2종(`z_seed1234`, `z_seed7777`,
선정 Student 와 동일 구성)이 큐에 있으며, 그 결과가 나오기 전까지:

- 선정 Student 의 −0.31%(p=0.114) 는 **"구분 불가"** 로만 쓴다. "더 좋다" 고 쓰지 않는다.
- KD 경계 Student 의 +0.42%(p=0.013) 도 **재검토 대상**이다. 시드 σ 가 0.5% 면 경계 자체가 흔들린다.
