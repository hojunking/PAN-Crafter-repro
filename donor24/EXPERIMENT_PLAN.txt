1. 이번 변경의 범위
두 서버 모두 WV3. s3의 과거 GF2 실험/기록/설정을 덮어쓰지 않는다.
이번 캠페인은 Stage 1 후보 탐색만 한다. Stage 2 자동 진입은 없다.
각 Stage 1 후보는 fresh A+Teacher 학습이다. 여러 후보를 찾는 단계와
선정 후 단일 donor로 모든 Stage 2 case를 비교하는 단계를 구분한다.
향후 s1/s3 Stage 2는 동일한 단일 A/T checkpoint 및 calibration을 공유한다.
각 서버가 서로 다른 local donor로 Stage 2를 시작하는 이전 규칙은 사용하지 않는다.

2. 현재 증거 및 탐색 이유
MASK2 DF07 donor 2벌: 50K 실측 2h29m19s / 2h28m59s (s1).
첫 donor best-HQNR=0.95761555, ERGAS=2.18925222, step14K.
둘째 donor best-HQNR=0.95267823: seed 차이가 크므로 단일 좋은 숫자를
설정의 안정적 우월성으로 해석하지 않는다.
이전 비마스킹 DF07 최고 HQNR=0.96079848/ERGAS=2.36143,
DF01=0.95624243/2.12840, DF04=0.95763311/2.17839.
이 숫자들은 탐색 방향의 근거이며 MASK2와 직접 효과 비교할 수 없다.
DF07 근방을 s1에서 세밀하게 탐색하고, s3는 낮은 absolute/epsilon
압력 및 낮은 Aligner LR을 탐색한다. 구조/epsilon 반경/데이터를 동시에
바꾸지 않아 loss/optimizer 효과를 우선 식별한다.

3. 고정 조건
WV3 8band, W112 d123 Teacher, native stored LMS로 DirectPANAligner 입력.
Teacher 입력 P0=aligned PAN+BICUBIC_MS. LPAN/HPAN 없음.
L = masked L1_rec + lambda_abs L_abs + lambda_epsilon L_epsilon.
Stage2의 e/q 가중치는 이 단계에 존재하지 않는다. eps는 epsilon loss 계수다.
Scharr RGB-mean-first absolute xy, /32, ROI8 그대로.
epsilon은 RR의 area-uniform disk radius3, 매 update, native anchor detach.
MASK2 detached bicubic4 support; per-sample valid 평균. 빈 support는 오류.
AdamW, Teacher LR1e-4, weight decay.01, batch48=12x4, FP32/AMP·TF32 off.
100 warmup + 원래 50K cosine. 14K 후보가 좋아도 14K cosine으로 바꾸지 않는다.
기존 augmentation 유지(H/V flip 항상 적용 + rot90); 이번에는 D4로 바꾸지 않는다.
각 admitted case 50K 완주; 성능을 보고 중도 가지치기하지 않는다.

5. 24시간 예산: 서버별 독립 wall clock, 총 서버 예산48시간
6 search +1 confirmation의 현재 s1 순수 실측 환산 약17.4h.
4K..20K 평가를 촘촘히 하므로 평가/저장 약0.5h 추가 예상.
1.2 안전계수와1h closeout, preflight를 포함해 약22~23h 계획.
이것은 추정이며 s3의 WV3 throughput은 아직 미측정이다.
각 서버가 disposable120-update, RR20/FR20 평가, probe/cost 시간을 측정한다.
모든 search admission 때 R2 한 벌을 먼저 예약한다.
elapsed + 1.2*(candidate50K + reserved_confirmation50K) +1h <=24h.
부족하면 큐 뒤 search를 SKIPPED_BUDGET 처리하고 confirmation을 우선한다.
50K를 몰래 단축하거나 예산을24h+R2로 늘리지 않는다.
재시작해도 최초 deadline 유지. 중단된 attempt는 보존, 재시도는 새 attempt.

6. 평가/저장/선택
공식 RR20 dim_cut21 / FR20 full512 unmasked, original PAN/native LMS 유지.
HQNR·SCC·ERGAS를 같은 checkpoint에서 평가하고 모두 print한다.
평가: step1000, 매2000, 25000, 그리고4000..20000 사이 매1000. 총35회.
기존 donor의 HQNR peak가6K..14K였기 때문에 평가 해상도만 높인다.
매 run best-HQNR 및 HQNR>=.959 중 최소 ERGAS checkpoint를 모두 보관.
threshold 통과 후보: ERGAS 최소, 동률 HQNR/SCC 우선.
통과 후보 없음: best HQNR -> SCC -> ERGAS의 탐색용 후보로 명확히 표시.
완료된 trajectory만 R2 설정/최종 local 후보 선택에 사용한다.
A/T는 반드시 같은 step. 실제 strict CPU reload와 최종 full40 재평가 검증.
후보 저장과 sheet의 joint-target 충족 판정은 별개다.
공식 평가를 선택에 사용하므로 test-aware 개발 실험이며 untouched test 주장은 하지 않는다.

7. 단일 donor 확정 절차
서버별 local_donor_candidate.json은 후보 추천이지 전역 donor 확정이 아니다.
24h 종료 후 두 서버의 후보 A/T 파일, SHA, 설정, source/evaluator hash,
RR20/FR20 및 R2 결과를 모아 같은 평가 환경에서 비교한다.
양 서버 A0/A1 차이로 환경·seed 변동을 확인하며 raw 절대값만으로
서버의 우열이나 설정의 통계적 우월성을 주장하지 않는다.
최종 하나의 checkpoint 파일 SHA + A/T state hash를 공통 donor로 잠근다.
Stage2 calibration은 그 최종 A/T에 바인딩하며 양 서버 동일 파일 사용.
원격 파일 취합/전송/Stage2 시작은 이 Stage1 runner가 자동 수행하지 않는다.

8. 진단과 cost
학습 loss별 raw/weighted 값, isolated A/T gradient norm을 기존 trainer가 기록.
8K/14K/20K/50K: 고정 RR/FR 입력의 shift response, gain, EPE, support.
이 probe는 geometric GT가 아니며 잘 맞는 응답이 실제 정합을 증명하지 않는다.
기존 unmasked gradient_probe는 재사용하지 않는다. 실제 masked forward의
학습 gradient 로그를 사용하고 추가 probe는 geometry-only로 제한한다.
cost는 각 서버 로컬의 동일 A+warp+Teacher graph 실측. s3에 s1 latency 복사 금지.
재사용 가능한 같은 서버·graph cost가 없으면 preflight 때 격리 측정한다.

예: A1 a2 eps0.003 lrA1e-05 R3 M2 R1
abs, epsilon loss 계수, Aligner LR, epsilon 반경, mask 버전, replica를 표시.
긴 Run_ID에는 서버/WV3/H50/전체 seed와 같은 핵심 값도 들어간다.

기존 qualified-steps-or-best-HQNR: WV3 HQNR>=.960 & ERGAS<=2.045인
모든 평가 step, 없으면 best-HQNR 대표행. donor gate .959와 혼동하지 않는다.
양 서버 모두 기존 WV3-ablations 사용. 서버 열은 실제 s1/s3 유지.
이 캠페인+자기 서버 소유 행만 갱신하고 신규 행은 appendCells로 추가한다.
기존 실험/다른 서버 행/시트 전체를 clear·replace·delete하지 않는다.
fallback->passing 전환 때 obsolete 자기 행 값만 지우며 행 이동/삭제는 없다.
원본 local ledger/outbox와 cloud 변경 전 snapshot 보존, readback 후에만 완료.
로컬 근거 없는 기존 자기 행/중복 ID/비정상 header/cost 누락이면 업로드 보류.

10. 실행
각 idle 서버에서 한 번:
  s1: bash scripts/run_donor24_docker.sh s1
  s3: bash scripts/run_donor24_docker.sh s3
데이터 다운로드, 기존 학습 중지, git commit/push는 자동 수행하지 않는다.
실행하면 preflight -> search -> local R2 -> 후보 저장까지 진행한다.
GPU 사용 중이면 명시적으로 거부한다. 기존 실험 종료는 별도 승인 후 수행.
새 launcher는 host uploader도 시작한다. s1의 인증된 동일 저장소 이전 sheet
writer만 handoff할 수 있고, 학습 프로세스와 s3의 과거 GF2 writer는 건드리지 않는다.
pull 자체는 학습 시작이 아니다. s3에 pinned WV3 원본 H5/DLPan 자산이 필요하다.
