# Scale30 게시 기준 변경 — 2026-10-23

사용자 확인에 따라 조건 충족 결과 게시와 case 대표 게시를 구분한다.
HQNR **0.9885 이상**, ERGAS **2.040 이하**인 결과는 모두 게시한다.
HQNR 기준을 만족하는 평가 중 ERGAS가 가장 낮은 결과 하나를 case 대표로 유지하며,
**대표에는 ERGAS 상한을 적용하지 않는다.** 이전 V3의 대표행 ERGAS gate는 해석 오류로 정정했다.
0.9885는 이번 지시의 수치이며, 이전 대화의 0.9585로 자동 교정하지 않는다.

## 적용 범위와 선정

- Campaign: `PANDA_S13_SCALE_HARDTUNE_30H_20261022_v1`, s1/s3의 Stage2.
- Policy: `PANDA_SCALE30_RRE_STAGE2_H9885_PASS_ALL_OR_REPRESENTATIVE_V4`.
- Destination: 기존 `pan-cvpr27-new` / `WV3-ablations`, sheetId `261001010`, A:BL.
- 같은 case라도 server/seed/run/attempt는 합치지 않는다. 기존 식별 단위마다 대표 1개와 조건 충족 step들을 게시한다.
- 공식 RR20/FR20을 동일 checkpoint로 평가한 원정밀도 값을 사용한다.
- HQNR ≥ 0.9885 후보를 ERGAS 오름차순 → HQNR 내림차순 → step 오름차순 → source ID로 정렬한다.
- 첫 후보를 ERGAS 상한과 관계없이 대표로 게시한다. HQNR 후보 자체가 없으면 대표도 없다.
- 공동 조건 충족 결과는 전부 게시하되, 대표와 동일한 checkpoint는 한 행으로 합친다.
- 대표는 고정 표시 ID로 갱신한다. 새 대표가 나오더라도 이전 대표가 공동 조건을 만족하면 충족 step 행으로 유지한다.
- 대표행에 `is_case_representative=true`와 실제 `publication_joint_pass`를 기록한다.
  ERGAS 상한을 초과한 대표는 `대표 · ERGAS 최소 · ERGAS 미달`로 표시하여 통과로 오인하지 않게 한다.
- 부등호는 양쪽 모두 inclusive다. 반올림 판정·OR 조건·HQNR 하한 미달 fallback·별도 final50K 행은 없다.
- 모든 metric과 cost는 선택된 동일 checkpoint의 identity에 결합한다.
- Stage1 donor는 기존 Val-RRE 선정·게시를 유지한다.

## 기존 실행과 원본 보존

변경은 `panda_scale30/best_publication/` 안의 게시 코드와 테스트에 한정한다.
학습·평가·체크포인트 저장 및 pruning 정책, donor, 실험 큐·예산은 변경하지 않는다.
기존 config와 immutable records/outbox의 .959/2.045 또는 HQNR-best 주석은 당시 기록이다.
새 게시기는 그 주석을 판정에 재사용하지 않고 원 평가 수치로 새 조건을 계산한다.
Sheet BI에는 새 publication policy/threshold/ranking을 별도로 기록한다.

기존 규칙에서 새 게시 집합에 남지 않는 행은 소유권·원본 평가 SHA·metric을 확인하고 cloud snapshot을 백업한 후
해당 서버/캠페인의 A:BL 값과 note만 비운다. 행 삭제로 다른 행을 이동시키지 않는다.
타 서버·과거 캠페인·paper·다른 탭·BM 이후 열은 변경하지 않는다.
raw 평가와 저장된 checkpoint는 로컬에 계속 남는다.

## 적용 명령

Git으로 변경을 받은 각 서버에서 **게시기만** 재시작한다.

```bash
# s1에서:
bash scripts/start_panda_scale30_best_publisher.sh s1 --restart
# s3에서:
bash scripts/start_panda_scale30_best_publisher.sh s3 --restart
```

기존 `publisher-<server>-best-hqnr-v1.log` 파일명은 운영 경로 호환을 위해 유지한다.
로그 파일명으로 정책을 판정하지 말고 아래 JSON의 실제 policy를 확인한다.

`work_dir/panda_scale30/PANDA_S13_SCALE_HARDTUNE_30H_20261022_v1/<server>/WV3/sheet_publish_panda_scale30/`

- `projection.json`: 위 V4 policy, publication_thresholds, Stage2 pass_count/kept_count 확인.
- `last_poll.json`: 위 V4 publication_policy, readback_verified=true 확인.
- `cloud_backup_*.json`: 기존 게시행 백업.
- `last_error.json`이 있으면 마지막 성공 시각과 비교하여 현재 오류인지 확인.

재시작은 동일 서버·동일 campaign root의 Sheet watcher만 식별해 교체한다.
학습 container 또는 GPU 작업을 정지하거나 다시 시작하지 않는다.

## 검증

`panda_scale30.tests.test_publication_scale`의 18개 테스트가 통과했다.
정확한 경계값, ERGAS 상한 초과 대표 유지,
모든 공동 조건 충족 step 게시, 대표 중복 제거, ERGAS 우선 선정, 동률 처리,
대표 변경 후 이전 충족 step 보존, 동일 표시 ID 갱신, V2/V3 migration,
원본 보존, foreign row/확장열 보존, readback을 검증했다.
변경 파일은 현재 s1 admission의 251개 code pin에 포함되지 않으며, pin 불일치는 0개다.
V3 최초 로컬 dry-run 당시 Stage2 129개 평가에 HQNR ≥ 0.9885 결과가 없어
공동 조건 충족도 대표 후보도 0개였다. V4에서도 HQNR 후보가 생기기 전까지 Stage1 donor 1행만 유지된다.
s3는 별도 에이전트가 Git 변경을 받아 위 명령으로 적용하고 readback을 확인해야 한다.
