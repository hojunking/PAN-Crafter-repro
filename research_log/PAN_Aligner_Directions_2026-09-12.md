## 1. 살아있는 것 — aligner 는 **작동한다**

폐기해야 할 것은 "aligner 가 안 된다" 는 요약이다. 데이터는 반대를 말한다.

| 사실 | 근거 |
|---|---|
| **어긋남을 정확히 맞춘다** | PO10 N2 \|Δ\|=1.511 · N3 1.906 px. 실측 PAN–MS 어긋남 **1.79 px** 의 **84~107%** |
| **방향도 맞다** | Δ=(+1.27,−0.79) — 센서 어긋남 부호와 일치, 20장 전부 |
| **스펙트럼은 오히려 좋아진다** | r(\|Δ\|, D_λ) = **−0.689**. PO10 D_λ **0.0112~0.0116** vs 무정합 0.0177 (−35%) |
| **정렬 프레임에서 보면 최상급** | `aligned_valid` HQNR 0.951~0.957, fSCC 0.918 vs raw 0.801 |
| **모듈 용량 문제가 아니다** | 합성 e~U(−2,2)² 에서 corr 0.997 · 오차 0.08 px (09-10 §9.4) |

막힌 곳은 **하나뿐**이다 — `D_s`(원 PAN 기준). r(\|Δ\|, D_s) = **+0.945**.

## 2. 왜 막혔나 — 프레임 하나로는 두 지표를 만족시킬 수 없다

`HQNR = (1−D_λ)(1−D_s)` 인데 **두 성분의 기준 프레임이 서로 1.79 px 어긋나 있다.**

- `D_λ` : 출력 ↔ **LRMS**(MS 프레임)
- `D_s` : 출력 ↔ **원 PAN**(PAN 프레임)

PAN 을 MS 쪽으로 당기면 D_λ 는 좋아지고 D_s 는 나빠진다. 반대도 마찬가지다.
**어느 한 프레임으로 출력을 보내면 반드시 다른 쪽을 잃는다.**

### 2.1 "프레임만 되돌리면 된다" 는 기각됐다 (이번에 실측)

가장 자연스러운 처방 — PAN 을 정렬해 내부에서 쓰고, **출력을 −Δ 로 되돌려** 원 프레임으로
내보낸다 — 를 학습 없이 직접 시험했다. `full_best_hqnr_mat20.mat` 을 −Δ 로 warp 해 재평가:

| P1 (frozen, \|Δ\|=1.511) | HQNR | D_λ | D_s |
|---|---:|---:|---:|
| 원본 출력 | 0.93298 | 0.02157 | 0.04659 |
| **출력을 −Δ 로 되돌림** | **0.89152** | **0.07046** | 0.04097 |

**더 나빠진다.** D_s 는 조금 회복(−0.006)되지만 D_λ 가 3.3배 폭발한다.
(재평가가 기록값 0.93298 을 5자리까지 재현했으므로 측정은 신뢰할 수 있다.)

→ **출력은 "옳은 영상이 틀린 프레임에 있는" 상태가 아니다.** 출력 안에서
**저주파(색)는 MS 에, 고주파(구조)는 warp 된 PAN 에** 각각 묶여 있다. 전역 shift 하나로는
둘을 동시에 고칠 수 없다. 09-09 가 잰 "출력 안에서 구조와 색의 기하가 ~1 px 어긋나 있다" 를
aligner 가 **더 벌린** 것이다.

### 2.2 그래서 P2 가 스스로 정합을 포기했다

P1·P2 는 같은 donor(\|Δ\|=1.511)에서 출발한다. 자유 학습한 P2 는 \|Δ\| 를 **0.344 (−77%)** 로
줄이고서야 HQNR 이 무정합 수준으로 돌아왔다. **현 손실 함수 아래에서 최적해는 "옮기지 말라"** 다.
aligner 를 살리려면 **옮길 이유를 손실이 실제로 보상해야 한다.**

## 3. 유망한 접근 — 우선순위

### A. 출력 프레임을 건드리지 않는 위치로 aligner 를 옮긴다 ★ 1순위

**근거.** 손상은 전부 "출력이 원 PAN 프레임을 떠난 것" 에서 온다(§2). 입력 PAN 을 warp 하면
출력이 따라간다. 그러나 **잔차 base(bicubic↑MS)와 출력 앵커를 원 프레임에 고정한 채
PAN 을 feature 수준에서만 정렬**하면 출력 프레임이 보존된다.

**설계.** `pa/model.py` 의 warp 를 입력단에서 **PAN 브랜치의 첫 feature 뒤로** 옮긴다.
`ms_base` 와 skip 경로는 원 좌표 유지. 출력 = base(원 프레임) + 잔차(정렬된 PAN feature 기여).

**반증 조건.** \|Δ\| 를 1.5 px 로 고정했을 때 D_s 가 무정합 수준(≈0.024)을 유지하지 못하면 기각.
D_λ 이득(−35%)이 사라져도 기각.

**비용.** 구현 소(warp 호출 위치 이동), 1벌 ≈ 2 h.

---

### B. 옮기지 말고 **알려준다** (conditioning) ★ 2순위

**근거.** 손상이 \|Δ\| 에 **비례**한다(r=−0.91). 즉 비용의 원인은 정보가 아니라 **이동 자체**다.
Δ̂ 는 정확하므로(§1) 정보만 쓰고 이동을 안 하면 비용 0 에서 이득만 남을 수 있다.

**설계.** aligner 는 Δ̂ 만 추정하고 warp 하지 않는다. Δ̂ 를 FiLM/embedding 으로 backbone 에
주입(MARs 의 mode γ/β 자리를 그대로 쓸 수 있다). 학습 신호는 기존 L_rec 그대로.

**반증 조건.** Δ̂ 주입이 HQNR·D_λ 어느 쪽도 판정선(0.0031) 이상 못 움직이면, Δ 는 이 backbone 에
쓸모없는 정보다 → aligner 축 종료 근거가 된다(**이게 가장 깨끗한 사망 판정 실험이기도 하다**).

**비용.** 구현 소, 1벌 ≈ 2 h. **A 와 독립이라 병렬 가능.**

---

### C. \|Δ\| ≤ 0.3 px 안전지대에서만 쓴다 ★ 3순위 (보조)

**근거.** \|Δ\| < 0.4 px 는 **완전히 공짜**다 — PA 3벌(0.19~0.25)·NF16 P2(0.344) 전부 판정선 안이고
W96 구간 r = +0.04 로 기울기 자체가 없다.

**설계.** aligner 출력에 `tanh` 로 하드 캡(±0.3 px). 다른 기법(KD·통계 loss)을 얹는 **안전한 바닥**으로 쓴다.

**한계.** 이 구간에서는 어긋남의 17% 만 보정하므로 **단독으로는 이득을 기대하지 않는다.**
"해를 안 끼치는 aligner" 를 확보하는 용도다.

---

### D. 주장할 지표를 바꾼다 — 내부 기하 일관성 ★ 연구 축

**근거.** HQNR 은 두 프레임이 어긋난 데이터에서 **구조적으로 정합을 벌한다**(§2).
aligner 가 실제로 개선하는 것(D_λ −35%, aligned fSCC 0.918 vs 0.801)은 HQNR 안에서 상쇄된다.
반면 09-09 가 정의한 **"출력 안의 구조–색 기하 어긋남"**(현재 ~1.2 px)은 프레임 중립 지표다.

**설계.** `tools/align_after_training_diag.py` 의 Part B(출력을 MTF 로 흐린 뒤 PAN·MS 각각과의 거리)를
**주 지표로 승격**해 aligner 유무를 비교한다. 이 값이 줄면 "영상이 실제로 더 일관되다" 를
HQNR 과 무관하게 주장할 수 있다.

**주의.** 판정 기준은 HQNR 로 불변이다. 이건 **보조 주장**이고, 논문에 쓰려면 HQNR 무손실을
함께 보여야 한다(→ A 또는 C 와 묶어야 의미가 있다).

---

### E. MS 쪽을 옮긴다 — **조건부**, 단독으로는 권하지 않는다

09-07 에서 유일하게 성공한 개입이 MS 조건 입력 jitter 였다(final HQNR +0.005~0.006).
그러나 **보정 목적의 MS warp 는 §2 의 대칭 문제**에 걸린다 — MS 를 PAN 프레임으로 옮기면
이번엔 `D_λ` 의 기준(원 LRMS)과 어긋난다. §2.1 의 −Δ 실험이 바로 그 방향의 증거다
(출력을 MS 에서 떼자 D_λ 가 3.3배 악화).
→ **무작위 jitter(정규화)로는 유효, 보정(correction)으로는 같은 벽.** A/B 뒤로 미룬다.
