# s5 실행 담당자 인계

Campaign `PANDA_G23_SENS_WV3_S45_20260923_v1`. s5만 처리한다. G23/WV3/P0/W104D121/T0 sensitivity이며 PLH/W104D122나 PAN-Crafter reproduction으로 바꾸지 않는다.

담당: calibration/aligner: QR05/QR20 (qref x.5/x2), TR05/TR20 (tau x.5/x2), RA01/RA06 (rA .01/.06). 매 cycle BASE1 + variants6, 각 fresh50K, seed0=1234; cycle>=1은2000000+cycle-1. 위 수치의 범위는 고정이며 결과에 따라 자동 수정하지 않는다.

읽을 순서: `EXPERIMENT_PLAN_KR.md` → `IMPLEMENTATION_HANDOFF_KR.md` → `config/runtime_bindings.example.json`.

1. 실제 기존 process/runner를 확인하고 현재 run 경계에서 신규 admission을 넘긴다. 다른 서버의 작업이나 과거 결과는 건드리지 않는다.
2. T0/cue/data/모델 signature와 actual coefficients를 확인하고 runtime bindings를 잠근다. NULL값은 로컬 실측으로 채운다.
3. 새 campaign namespace에 trainer/evaluator/state/outbox를 연결하고 GPU smoke·resume·gradient routing 검사를 통과시킨다.
4. 이 서버의 lazy iterator를 한 case씩 소비한다. 완료 결과를 검증하기 전 다음 cursor로 넘어가지 않는다. 다른 서버를 기다리는 lock은 없다.
5. Sheet 탭은 `SENS-G23-WV3-s5`. EXACT50K primary, validation secondary. 낮은 metric이나 높은 metric 때문에 중단/seed 재추첨하지 않는다.

Case 확인 명령(학습을 시작하지 않음):
```bash
python tools/casegen.py next --server s5 --cycle 0 --position 0
```

실제 배포 전후의 PID, frozen source, source/data/Teacher/cue hashes, 첫 baseline run_id, GPU smoke/eval/Sheet readback 여부를 분리해서 보고한다. 본 문서만 전달받은 상태를 가동 완료로 보고하지 않는다.
