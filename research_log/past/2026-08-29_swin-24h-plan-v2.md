# Swin hybrid 24h 실험 계획 v2 — s1·s2 (2026-08-29)

원안: [`2026-08-28_swin-24h-s1-s2-plan.md`](2026-08-28_swin-24h-s1-s2-plan.md).
이 문서는 [24h 탐색 결과](../results_log/2026-08-29_arch-search-24h-results.md)를 전제에
반영한 수정 제안이다. **원안과 다르면 이 문서를 따른다.**

## 0. 원안에서 바뀐 것 4가지

1. **판정선 교정.** `|ΔHQNR| < 0.001` 동급 기준은 확정 노이즈(2σ ≈ 1.18% ≈ **0.011**)의
   1/10 이라 난수 분기가 된다. 동급 기준을 0.011 로 올리고, 동급이면 CLAUDE.md 순위대로
   SCC → ERGAS 로 보조 판정한다(ERGAS 유의선은 3σ ≈ **0.3%**). ERGAS "5% 악화 시에만
   경고"는 폐기 — c6→c8 붕괴 전체가 5.7%였다.
2. **CM3A 대조군 추가 (구현 0줄).** SW2 가 이겨도 "Swin 이라서"인지 "bottleneck 에
   attention 이 있어서"인지 구분이 안 된다. `c6 + attn_locations:[btl]` 한 벌로 귀속을
   가른다 — 직전 캠페인 c3b(HQNR 명목 1위)는 d224 기반이라 d124 조합은 미측정이다.
3. **D024 vs BTL2 는 ERGAS 로 판정.** HQNR 는 무판별이 확정이므로 "HQNR 동급이면
   D024"는 자동 승리 규칙이 된다. R1 이 입증한 full-res 제거의 숨은 비용(+2.28%)을
   ERGAS 가 잡아야 한다. 사전 예측: **BTL2 우세** (bottleneck 이 가장 싼 자원).
4. **LR-TinySwin 은 반증 1벌만.** LR-Fuse(0.54M)가 ERGAS 4.0+ 로 기각된 패러다임의
   더 작은 판(0.2~0.4M)이다. SW2 한 벌(0.8h)로 "Swin 전역 attention 이면 다른가"만
   반증하고, 조건부 SW4 는 삭제(생존선 HQNR ≥0.950 은 실질 도달 불가).

Swin 공통 설정은 원안 §1.2 그대로: H/4 bottleneck ResBlock 뒤, embed 128(=width),
heads 4, window 8, shift 0/4 교대, MLP ratio 2, LN, rel-pos bias, W→SW 쌍 단위.
학습 16²·RR 64²·FR 128² 격자가 전부 window 8 의 배수라 padding 불필요.

## 1. 판정 규칙 (전 case 공통)

```text
best 선택      = HQNR (공식 12-19, 불변)
동급 기준      = |ΔHQNR| < 0.011 (2σ). 동급이면 SCC → ERGAS 로 보조 판정
ERGAS 유의선   = 0.3% (3σ). 이보다 작으면 차이를 주장하지 않는다
HQNR 하한 가드 = anchor 대비 −0.011 초과 하락이면 그 갈래 경고
동급이면       = 더 작고 빠른 쪽을 선택 (원안 규칙 유지)
```

## 2. s1 — Swin 용량 사다리 + 귀속

전 case: c6 골격(w128·d124·11ch·dual MARs·nocrop·LN·50K). Swin/attention 만 바꾼다.

| # | 실행 (config) | bottleneck 구성 | 추정 params | 예상 학습 | 확인 질문 |
|--:|---|---|---:|---:|---|
| 1 | `CM3A_btl_d124` | Res×4 + **CM3A AttnBlock** | ≈4.39M | 2.5h | 귀속 대조군 — 자체 attention 의 몫 |
| 2 | `SW2_btl` | Res×4 + Swin×2 | ≈4.04M | 2.8h | Swin 존재 효과 (s2 와 공통 anchor) |
| 3 | `SW4_btl` | Res×4 + Swin×4 | ≈4.31M | 3.1h | 용량 확대 1 |
| 4 | `SW2_mid` | Res×4 (btl 은 그대로) + **H/2 enc 에 Swin×2** | ≈4.04M | 3.0h | 위치 질문 — "고해상도 인접 용량이 핵심"이면 attention 도 H/2 가 나은가 |
| 5 | 조건부 `SW6_btl` | Res×4 + Swin×6 | ≈4.57M | 3.4h | 포화점 |
| 6 | 조건부 `SW8_btl` | Res×4 + Swin×8 | ≈4.84M | 3.7h | 상한 |

게이트 (`campaign_gate.py` 확장, ERGAS 는 DLPan 프로토콜·HQNR 는 best_state.json):

```text
SW6: SW4 ERGAS ≤ SW2 ERGAS × (1 − 0.003) 이고 HQNR 하한 가드 통과일 때만
SW8: SW6 이 같은 조건으로 SW4 를 이길 때만
```

확정분 1–4 = 11.4h. 게이트가 다 열려도 18.5h + 구현·smoke ≈ 21h 로 24h 안.
현실적 기대: 사다리는 SW4 근처에서 정체 판정 — 그 자체가 답이다.

**해석 매트릭스**: SW2>CM3A>c6 이면 Swin 고유 가치. SW2≈CM3A>c6 이면 "attention 이
있으면 된다"(표준 Swin 의 서사 이점만 남음). 둘 다 ≈c6 이면 bottleneck attention 무용
(직전 캠페인 c4 의 ERGAS +2.38% 는 enc/dec attention 몫으로 재귀속). SW2_mid 가
SW2_btl 을 ERGAS 로 이기면 위치 우선순위가 저해상도→고해상도로 뒤집힌다.

## 3. s2 — Swin 유지 축소 + 앵커·확정 실험

s2 는 `work_dir/cases_queue.txt` 로 큐를 정의한다 (러너 v2, git 비추적).

| # | 실행 (config) | 무엇 | 추정 params | 예상 학습 | 확인 질문 |
|--:|---|---|---:|---:|---|
| 1 | `c6_c4d124` (기존 config) | c6 재현 | 3.77M | 2.4h | s2 내부 no-attention 앵커 |
| 2 | `SW2_btl` (s1 과 동일 config) | 공통 anchor | ≈4.04M | 2.8h | 서버 간 Swin 효과 공통 기준 |
| 3 | `SW2_btl_d024` | SW2 + depth(0,2,4) | ≈3.27M | 2.2h | full-res 제거를 Swin 이 벌충하는가 (R1 의 +2.28% 회복 여부) |
| 4 | `SW2_btl_res2` | SW2 + btl ResBlock 4→2 | ≈3.45M | 2.6h | matched-budget 상대 — bottleneck 이 정말 싼 자원인가 |
| 5 | 조건부 `SW2_btl_<승자>_w112` | 승자 폭 112 | ≈2.5M | 2.4h | hybrid 에서의 폭 축소 기울기 |
| 6 | `N3_9_d124_noattn` (기존 config) | N3 재현 | 3.77M | 2.4h | **9ch 성립의 서버 독립 확정** (입력 통일 결정용) |
| 7 | `LR_SW2_w64` | LR-TinySwin | ≈0.25M | 0.8h | LR 패러다임 반증 (Swin 전역 attention 판) |

- #3 과 #4 는 params 가 정확히 같지는 않다(3.27 vs 3.45M — dec_depth 미러 시맨틱이
  decoder 융합 블록까지 제거). matched-budget 은 근사로 취급하고 ERGAS·latency 로 판정.
- #5 게이트: 승자가 SW2_btl 대비 ERGAS +1.5% 이내일 때만 (아니면 축소 갈래 정보 없음).
- #7 판정: HQNR ≥0.940 또는 ERGAS ≤2.60 이면 예상 밖 생존 — 그때만 후속 논의.
  기대는 기각 확인이다.

확정분 1–4·6–7 = 13.2h, #5 포함 15.6h — 24h 안 (s2 는 구현 대기 없음, pull 만).

## 4. 구현 목록 (s1 에서 작업, 커밋 후 s2 pull)

1. `model/swin.py` — `SwinBlock`(W/SW-MSA, rel-pos bias, mask) 직접 구현. 외부 의존성 없음.
   mode 조건화 없음(ModeModulation 은 ResBlock 담당) — 표준형 유지가 서사에도 유리.
2. `model/pancrafter_paper.py` — `swin_depth`(btl, ResBlock 뒤) · `swin_mid`(H/2 enc) 옵션.
   미지정 시 기존과 완전 동일(체크포인트 호환 확인 필수 — c0·c6 params 불변 검사).
3. `model/lr_tinyswin.py` — 원안 §5.2 구조. forward 계약은 기존과 동일(잔차, dual MARs).
4. `tools/smoke_cases.py` — window 왕복(`shuffle(unshuffle(x))==x`), shift mask,
   impulse 국소성, PAN/MS 별 non-zero grad 검사 추가 (원안 §5.4 반영).
5. `tools/campaign_gate.py` — SW 사다리·w112 게이트 추가 (HQNR 는 best_state.json 재사용).
6. gspread — `swin{n}@btl/mid` 서술자·Notes 확장.

구현 ≈ 2h + smoke. 검증: 기존 config 회귀(params·state_dict 키 불변) + 신규 전 config smoke.

## 5. 예상 산출물

```text
s1: Swin 존재/귀속/위치/포화 곡선 (CM3A 대조 포함)     — Teacher 후보 갱신 여부
s2: c6·N3 서버 독립 재현 + Swin 유지 축소의 ERGAS 곡선  — Student 후보 갱신 여부
```

- SW hybrid 가 c6 를 ERGAS 3σ 이상으로 이기면 Teacher 후보 교체 검토.
- 아니면 c6(또는 9ch 확정 시 N3)가 Teacher, R1 계열이 Student 로 확정되고
  다음 캠페인은 KD 파이프라인(T→S, full·H/2 feature 증류 우선)으로 넘어간다.

## 6. (추기) 설계 검증 패스 반영 — 본문과 다르면 이 절을 따른다

3방향(커버리지·실현성·교란) 적대 검증에서 나온 수정. 코드로 해결된 것은 [코드] 표시
(구현 보고서: [`2026-08-29_swin-implementation-report.md`](2026-08-29_swin-implementation-report.md)).

1. **[코드] 잔존 상태 함정** — 지난 마감 파일·이전 DONE 로그·구 큐 그대로면 새 체인이
   시작 즉시 무산된다. `tools/campaign_start.sh` 가 마감 갱신·로그 회전·큐 검증·기동을
   일괄 처리한다. **양 서버 모두 새 캠페인은 반드시 이 스크립트로 기동할 것.**
2. **[코드] 2단 게이트(SW6→SW8) 도달 불가** — 러너의 게이트 단계를 다중 패스 루프로
   변경(새로 열리는 것이 없거나 마감까지 반복). SW8 이 실제로 도달 가능해졌다.
3. **[코드] config 부재 ≠ 실패** — smoke 가 config 부재를 exit 2 로 구분, 체인은 원장에
   남기지 않고 그 패스만 건너뛴다(s2 가 pull 전에 기동해도 캠페인이 무산되지 않는다).
   그래도 **s2 큐 순서는 c6 → N3 → (Swin 의존 5건)** 으로 바꿔 4.8h 버퍼를 둔다.
4. **순수 용량 대조군 추가** — SW2>c6 이 "params +0.27M 때문"일 가설을 가르는
   `c6 + depth [1,2,6]`(btl ResBlock +2, ≈4.36M, 구현 0줄) 한 벌을 s1 에 추가.
   matched-budget 귀속 짝은 **CM3A(4.39M) vs SW4(4.31M)** 로 재정의한다.
5. **CM3A 대조군 명세 확정** — `cm3a_pan_branch: false`(c3b 계열 MS-only) 명시.
   실측 4.3921M. config 에 `expect_params_m` 을 넣어 옵션 누락을 smoke 가 잡는다
   [코드: smoke 의 expect_params_m 검사].
6. **ERGAS 유의선 교정** — 두 단일 실행 차이의 3σ = **0.23%** (2σ=0.11%·√2).
   본문의 0.3% 는 "3σ" 라벨을 떼고 **운영 게이트(≈4σ, 슬롯 비용 정당화용)** 로 유지.
   D024/BTL2 등 구조 판정에는 0.23% 를 쓴다. 게이트가 닫힐 때 관측 Δ와 σ배수를
   로그에 남긴다.
7. **해석 매트릭스 보강** — (a) CM3A>SW2 행: "c6+CM3A_d124 가 Teacher 후보, 표준 Swin
   서사 기각" (b) SW2<c6 행: Swin 갈래 종료, CM3A·용량 대조 결과만 기록.
   "둘 다 ≈c6 → c4 의 +2.38% 재귀속" 은 **d124 한정**으로 한정한다 — depth×attention
   상호작용(직전 캠페인 §2.4)이 있어 d224 의 c3b 효과와 단순 비교할 수 없다.
8. **LR-TinySwin 은 L1 과 params 매칭** — 0.25M 판은 실패가 과잉결정된다(L1 0.54M 의
   절반). `LR_SW2_w128`(≈0.59M, L1 과 동급)로 바꿔야 "Swin 이라서 다른가"에 답한다.
9. 구현(≈2h)은 s1 1번 case(CM3A, 구현 0줄·2.5h)의 학습과 병렬로 진행해 흡수한다.
