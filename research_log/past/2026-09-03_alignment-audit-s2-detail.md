# I. 분석 진행

## 0. 대상과 단위

**비교 대상 확인.** 이 문서의 `PAN` 은 판크로매틱을 MS 해상도로 내린 단일 밴드 영상,
`MS` 는 **LRMS**(h5 의 `ms`)의 밴드 평균이다. **GT 가 아니다.**
FR 에는 GT 가 존재하지 않고(`lms`·`ms`·`pan` 뿐) LRMS 가 실제 관측이며,
RR 에는 GT 가 있고 LRMS 는 거기서 합성된다(pair A 가 이를 확인한다).


| 센서 | 학습 | RR test | FR test | 비고 |
|---|---|---|---|---|
| WV3 | 9,714 패치 | 20 (8밴드) | 20 (repaired) | |
| QB | 17,139 | 20 (4밴드) | 20 (repaired) | |
| GF2 | 19,809 | 20 (4밴드) | 20 (repaired) | |
| WV2 | 없음 | 20 (8밴드) | 20 (**repaired 없음**) | F-1 미적용 |

**부호 규약** (계획 §4): `δ_{A←B}` = B 를 옮겨 A 에 맞추는 양.
구현 정의는 `aligned[y,x] = mov[y+dy, x+dx]`, 즉 `mov = ndimage.shift(ref,[dy,dx])` 에
estimator 가 `(dy,dx)` 를 돌려준다. impulse test 로 매 실행 검증한다.

**측정 격자.** PAN-Crafter 는 항상 **PAN 격자**에서 동작한다 — `train.py:156` 이
`res_ms = F.interpolate(ms, scale_factor=4, mode="bicubic")` 로 MS 를 올린 뒤 잔차를 더한다.
따라서 두 격자에서 각각 재고 둘 다 보고한다.

- **MS 격자**: MTF↓(PAN) ↔ `ms`. 두 영상이 같은 해상도라 가장 깨끗한 측정.
- **PAN 격자(모델 시점)**: blur(PAN, MS 해상도) ↔ up(MS). 모델이 실제로 보는 배치.
  **해상도를 맞추지 않으면 값이 부풀려진다** (§III-3).

## 1. Pair 정의 (계획 §3)

| pair | ref | mov | 목적 |
|---|---|---|---|
| A `lrms_gt` | MTF↓(GT) | MTF↓(LMS) | GT–LRMS 생성 파이프라인의 일관성 |
| B `pan_gt` | MTF↓(PAN) 구조 | MTF↓(GT) 구조 | GT 가 PAN geometry 를 따르는가 |
| C `pan_lrms` | MTF↓(PAN) 구조 | MS 구조 | **실제 모델 입력의 정합 상태** |

## 2. Estimator (계획 §5)

- primary: Scharr gradient magnitude → median/MAD 정규화 → 상위 30% edge mask → ZNCC 격자탐색
- secondary: census(5×5) + Hamming
- subpixel: 정점 3×3 quadratic fit
- 신뢰도: peak margin, boundary hit, primary–secondary 일치도(§8)

## 3. Phase 1 — estimator 사전 검증 (게이트)

실데이터 20 패치·4 센서에 알려진 이동을 걸었다.

| 기준 (§6.4) | 실측 | 판정 |
|---|---|---|
| integer 복원 오차 ≤0.5 LR px, 95% 이상 | **100%** (중앙 0.012px, 최대 0.043px) | 통과 |
| identity center 복원 99% 이상 | **100%** (정수 peak 전부 (0,0)) | 통과 |
| 부호 규칙 100% | **100%** | 통과 |
| negative < positive | ZNCC **0.131 vs 0.997** | 통과 |
| (참고) subpixel | 중앙오차 **0.081px**, ≤0.5px 100% | — |

## 4. Phase 0 — MTF 연산이 데이터셋과 같은가 (게이트)

`ms` 를 우리 연산으로 재현할 수 있어야 pair C 의 값이 데이터를 잰 것이 된다.

| downsample | \|shift\| vs 데이터셋 ms | ZNCC |
|---|---:|---:|
| gaussian σ=1.98 + decimate **phase 0** | 0.621 LR px | 0.870 |
| gaussian σ=1.98 + decimate **phase 2 (= scale//2)** | **0.017** | **0.9999** |
| block mean | 0.116 | 0.985 |

phase 2 채택. 4 센서 전부 ZNCC ≥ 0.9999 · 강도상관 ≥ 0.9997.
`validate_mtf.py` 가 매 실행 확인하고 실패하면 audit 을 중단한다.
**부수 소득**: 저장소의 σ=1.98 가우시안 근사가 PanCollection MTF 와 사실상 동치다.

## 5. Phase 2–4 — 스캔

- Phase 2 train: 패치가 LR 16×16 이라 §7 의 24px window 분해가 불가능 → **HR 64×64 격자**에서
  분해(해상도 맞춤 필수, §III-3). 센서당 ~200 패치.
- Phase 3/4 RR·FR: 장면당 dense local field(24px window, stride 8) → robust global
  (weighted median + RANSAC) → robust affine(IRLS Cauchy) → residual. 240 + 80 레코드.

## 6. Phase 5 — 잔차가 어디에 몰리나

전역 보정 후 dense optical flow(TV-L1)의 크기 지도에서 연결성분을 뽑았다.

## 8.5 edge 를 만드는 기준 자체가 편향돼 있지는 않은가

PAN 은 단일 광대역, LRMS 는 다분광 밴드 평균이다. 결과가 강건한지(§8.5-c)와 **기준 자체가
편향됐는지**는 다른 질문이므로, **참값이 0 인 쌍**을 만들어 파이프라인이 무엇을 내놓는지 쟀다.

**LRMS 쪽 경계 추출.** LRMS 는 128×128 의 실제 영상이다. 밴드 평균 → Scharr gradient
magnitude → median/MAD 정규화 → 상위 30%. **magnitude(부호 없음)라 PAN 에서 밝고 MS 에서
어두운 지형도 대응된다.**

### (a) 해상도·edge 생성 편향 — 없다

# III. 이슈 — 과정에서 겪은 것

## 1. MTF decimation 위상 (거짓 결론 직전까지 갔다)

첫 스캔에서 `pan_lrms` 만 −0.3~−0.6 LR px 어긋나 보였는데 `lrms_gt`·`pan_gt` 는 0 이었다.
A≈0, B≈0 인데 C≠0 이면 삼각 일관성이 깨진 것이라 데이터가 아니라 코드를 의심해야 했다.
원인은 decimation 위상 0 (정답 2)이었고, 그 오차 0.62 LR px 가 그대로 가짜 misalignment 로
나타났다. **교훈**: 데이터셋이 제공하는 산출물을 우리 연산으로 재현할 수 있는지 먼저 확인한다.

## 2. §6.1 identity 판정 기준

계획의 "identity center recovery 99% 이상" 을 비트 단위 0 으로 읽으면 실데이터에서 통과가
불가능하다(첫 실행 0%). quadratic subpixel fit 은 이웃 비대칭으로 정확히 0 이 되지 않는다.
정수 peak (0,0)·ZNCC 1.000000, subpixel 잔차 최대 0.043px 이므로
**정수 peak (0,0) + subpixel 잔차 ≤0.1px** 으로 정의했다.

## 3. 측정 격자·해상도 불일치로 인한 부풀림

train 을 HR 격자에서 분해했더니 전역 \|δ\| 가 0.30~0.38 LR px 로 나와 RR test(0.07~0.10)와
어긋났다. HR 격자에서는 선명한 PAN 과 매끄러운 up(MS) 를 비교하게 되어 gradient 위치가
편향된다. PAN 을 MS 해상도로 blur 하면:

| 센서 | LR 격자 | HR·원본 PAN | HR·해상도 맞춤 |
|---|---:|---:|---:|
| QB | 0.082 | 0.521 | **0.114** |
| GF2 | 0.049 | 0.409 | **0.063** |

이후 전 PAN-격자 측정에 해상도 맞춤을 적용했다. **pair C 는 처음부터 MS 격자에서 맞춰 쟀으므로
영향 없다.** **교훈**: 격자를 바꿔 수치가 달라지면 해상도부터 의심한다.

## 4. 교차검증 도구 자체의 편향

`skimage.phase_cross_correlation` 은 부호가 우리 규약과 반대이고 설정에 따라 크기를 20%
과소추정한다. 알려진 이동으로 격자 탐색해 무편향 설정을 골랐다
(`normalization=None` + Hanning window, 평균 절대오차 0.029px; 최악 설정 0.072px).
**교차검증 도구를 먼저 교정하지 않으면 대조가 무의미하다.**

## 5. 국소 보정 구현이 판정을 결정했다 (판정이 뒤집혔다)

첫 판정 "국소 이득 없음" 은 국소 field 를 **역거리 가중 보간**으로 구현한 결과였다.
그 field 는 구조적으로 매끄러워 국소 변위를 못 잡는 쪽으로 편향된다 — 국소 가설을 불리하게
시험한 셈이다. dense optical flow(TV-L1)로 다시 재니 이득이 +0.038~+0.045 로 판정선(0.005)의
8~9배였다. **교훈**: 가설을 기각할 때는 그 가설에 가장 유리한 구현으로 시험했는지 먼저 묻는다.
동시에 과적합 대조를 반드시 붙인다(§II-5).

## 6. fSCC 이득이 보간 인공물일 가능성

예시 그림의 단면 한 줄에서 보정 후가 나빠 보여 의심했다. 영-이동을 같은 보간 경로로 통과시켜
fSCC 변화 0.0000 을 확인하고, shift 를 −1~+1 훑어 최적점이 추정치와 0.14~0.16px 내에 있음을
확인했다. **단면 한 줄은 대표성이 없다.**

## 7. 미해결

- 국소 잔차의 물리적 원인(잔여 resampling 오차 vs 지형 기복)은 가르지 못했다.
- 국소 이득의 **크기**는 구현 의존이다(TV-L1 +0.043 vs ILK +0.013). 방향만 신뢰한다.
- WV2 는 학습셋이 없고 FR 도 F-1 복구가 적용되지 않았다 — 이력이 다르다.
- §II-4 의 반 픽셀 오차가 학습 성능에 미치는 영향은 미측정이다(`residual_base: lms` 로 재학습해야).
- 정합 보정 후 HQNR 재측정 미실행 — 요약본 §6 의 가설은 아직 가설이다.
