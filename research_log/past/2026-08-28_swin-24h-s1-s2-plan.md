# c6 기반 Swin 24시간 s1·s2 실험 계획 (2026-08-28)

## 0. 목적과 판정 우선순위

현재 Pareto 후보 `c6_c4d124`를 공통 출발점으로 삼아 다음 세 질문에 답한다.

1. c6 bottleneck에 표준 Swin Transformer를 추가하면 HQNR이 개선되는가?
2. Swin depth를 늘렸을 때 개선이 계속되는가, 어느 지점에서 포화되는가?
3. Swin을 유지하면서 CNN 및 전체 파이프라인을 어디까지 줄일 수 있는가?

seed 반복은 하지 않는다. s1과 s2의 동일 `SW2-ADD` 실행은 seed 검증이 아니라 각 서버에서 Swin 효과를 읽기 위한 공통 anchor다.

판정 순서는 다음과 같다.

```text
1. HQNR
2. inference latency
3. params / peak memory
4. D_lambda / D_s 분해
5. ERGAS는 c6 대비 5% 이상 악화할 때만 경고·보류
```

`|ΔHQNR| < 0.001`은 동급으로 보고, 동급이면 더 작고 빠른 모델을 선택한다.

---

## 1. 공통 기준 구조

### 1.1 c6

```text
Input: 11ch
Width: 128
Depth: [1, 2, 4]
Attention: 없음
MARs: dual

Encoder
  H   : ResBlock ×1
  H/2 : ResBlock ×2

Bottleneck H/4
  ResBlock ×4

Decoder
  H/2 : ResBlock ×2
  H   : ResBlock ×1

Output
  3×3 residual head
  + upsampled MS
```

기존 s1 실측:

| HQNR↑ | D_lambda↓ | D_s↓ | Params | Infer | Memory | Train |
|---:|---:|---:|---:|---:|---:|---:|
| 0.9536 | 0.0213 | 0.0256 | 3.7719M | 6.63ms | 283.3MB | 2.40h |

### 1.2 공통 Swin 설정

```text
위치          = H/4 bottleneck, 기존 ResBlock 뒤
embed_dim     = 128
heads         = 4
window        = 8×8
shift         = 0 / 4 교대
MLP ratio     = 2
dropout       = 0
norm          = LayerNorm
position      = relative-position bias
patch merge   = 없음
class token   = 없음
best 선택     = HQNR
```

Swin block의 배열은 항상 `W-MSA → SW-MSA` 한 쌍을 기본 단위로 한다.

### 1.3 `SW2-ADD` — 두 서버 공통 첫 case

```text
Bottleneck
  ResBlock ×4
  Swin W-MSA
  Swin SW-MSA
  → UpConv
```

예상 파라미터:

| 항목 | Params |
|---|---:|
| c6 전체 | 3.7719M |
| Swin block ×2 | 약 0.2668M |
| **SW2-ADD 전체** | **약 4.0387M** |

이는 PAN-Crafter 7.173M보다 약 43.7% 작다. Swin 두 블록의 window partition, cyclic shift, attention mask, softmax, reshape에는 학습 파라미터가 없다.

## 2. 전체 실험 설계

```text
                              c6
                               │
                    bottleneck Swin ×2 추가
                       공통 기준: SW2-ADD
                          /           \
       s1: Transformer capacity↑       s2: CNN/pipeline capacity↓
       SW2→SW4→SW6→SW8                 D024 / BTL2 / width↓
                                               +
                                          LR-TinySwin
```

s1과 s2에서 architecture family를 섞지 않는다. 모든 Transformer case는 같은 Swin block을 사용한다.

---

## 3. s1 — Swin depth 확대

### 3.1 고정 변수

다음은 모든 s1 case에서 동일하다.

```text
c6 CNN backbone
width 128
depth [1,2,4]
11ch input
dual MARs
window 8
heads 4
MLP ratio 2
```

Swin block 수만 바꾼다.

### 3.2 Case

| 순서 | ID | Bottleneck | 예상 총 Params | 성격 |
|---:|---|---|---:|---|
| 0 | 기존 `c6` | ResBlock×4 | 3.7719M | no-attention anchor |
| 1 | **`S1_SW2_ADD`** | ResBlock×4 + Swin×2 | **4.0387M** | 공통 Swin 관문 |
| 2 | **`S1_SW4_ADD`** | ResBlock×4 + Swin×4 | **4.3054M** | capacity 확대 1 |
| 3 | **`S1_SW6_ADD`** | ResBlock×4 + Swin×6 | **4.5722M** | capacity 확대 2 |
| 4 | 조건부 `S1_SW8_ADD` | ResBlock×4 + Swin×8 | 4.8390M | 포화 확인 |
| 5 | 조건부 `S1_SW10_ADD` | ResBlock×4 + Swin×10 | 5.1057M | 상한 확인 |

Swin 배열:

```text
SW2  = W / SW
SW4  = W / SW / W / SW
SW6  = W / SW / W / SW / W / SW
```

### 3.3 실행 분기

```text
SW2
→ SW4
→ SW6
→ 조건부 SW8
→ 조건부 SW10
```

- `SW2 - c6 ≥ +0.001 HQNR`: SW4·SW6 진행.
- `|SW2 - c6| < 0.001`: SW4까지 실행해 얕은 모델의 용량 부족 여부를 확인.
- `SW2 - c6 ≤ -0.001`: SW4 한 번만 확인하고 확대 중단.
- 직전 depth 대비 HQNR 증가가 `+0.0005` 미만이면 다음 depth를 중단.
- 두 단계 연속 HQNR 정체·하락이면 종료.
- latency가 직전 단계보다 15% 이상 늘고 HQNR 증가가 0.001 미만이면 종료.

### 3.4 예상 시간

| Case | 예상 학습 |
|---|---:|
| SW2 | 2.7~3.0h |
| SW4 | 3.0~3.4h |
| SW6 | 3.3~3.8h |
| SW8 | 3.7~4.3h |
| SW10 | 4.0~4.8h |

SW2~SW6은 약 10시간, SW8·SW10까지 실행하면 약 19시간이다. 구현·smoke·평가를 포함해 24시간 안에 둔다.

### 3.5 s1 최종 산출물

```text
Swin depth : 0 → 2 → 4 → 6 → 8(→10)
Params     : 3.77 → 4.04 → 4.31 → 4.57 → 4.84M
HQNR       : 실측
D_lambda   : 실측
D_s        : 실측
Latency    : 실측
```

목표는 Swin의 존재 효과와 capacity–HQNR–latency 포화점을 한 곡선으로 얻는 것이다.

## 4. s2 — Swin을 유지한 CNN 축소

### 4.1 공통 anchor

s2에는 아직 c6 결과가 없으므로 다음 두 case를 우선 실행한다.

| 순서 | ID | 목적 |
|---:|---|---|
| 1 | **`S2_C6_ANCHOR`** | s2 내부 no-attention 기준 |
| 2 | **`S2_SW2_ADD`** | s2 내부 Swin 효과 |

이후 Swin pair는 고정하고 CNN 용량만 줄인다.

### 4.2 matched-budget 비교

두 모델은 약 3.45M으로 파라미터가 같지만 제거 위치가 다르다.

| ID | 제거 대상 | Bottleneck | 예상 Params | 기대 효과 |
|---|---|---|---:|---|
| **`S2_SW2_D024`** | full-resolution ResBlock 2개 | Res×4 + Swin×2 | 약 3.446M | latency 절감 큼 |
| **`S2_SW2_BTL2`** | bottleneck ResBlock 2개 | Res×2 + Swin×2 | 약 3.446M | 고해상도 공간 경로 유지 |

#### `S2_SW2_D024`

```text
Encoder H   : ResBlock 1 → 0
Decoder H   : ResBlock 1 → 0
H/2         : 기존 유지
H/4         : ResBlock ×4 + Swin ×2
```

#### `S2_SW2_BTL2`

```text
Encoder/Decoder H : 기존 유지
H/2                : 기존 유지
H/4                : ResBlock 4 → 2 + Swin ×2
```

판정:

- HQNR 동급이면 `D024` 선택: 같은 params에서 full-resolution 연산이 적다.
- `BTL2`가 HQNR에서 0.001 이상 높으면 고해상도 공간 보정의 가치가 있다고 판단.
- 둘 다 `SW2-ADD` 대비 HQNR −0.003 이하이면 CNN 축소 갈래를 중단.

### 4.3 width 축소

matched-budget 승자 하나만 width 축소한다.

| ID | Width | 예상 Params | 실행 조건 |
|---|---:|---:|---|
| **`S2_SW2_W112`** | 112 | 약 2.6~2.8M | matched-budget 승자 확정 후 |
| 조건부 `S2_SW2_W96` | 96 | 약 1.9~2.1M | W112가 통과한 경우 |

분기:

- W112가 W128 승자 대비 HQNR −0.001 이내: W96 진행.
- W112가 −0.001~-0.003: latency가 25% 이상 감소할 때만 W96 진행.
- W112가 −0.003 이하: width 축소 종료.

## 5. s2 — 초소형 `LR-TinySwin`

### 5.1 목적

c6 U-Net을 줄이는 갈래와 별도로 0.2~0.4M급 ultra-lite Pareto를 찾는다. LR 공간에서 처리하고 마지막에 PixelShuffle로 복원하는 표준 sub-pixel SR 흐름을 사용한다.

### 5.2 구조

```text
PAN 256×256×1
  → PixelUnshuffle ×4
  → 64×64×16

LRMS 64×64×8
  → concatenate
  → 64×64×24

3×3 Conv
  → 64 channels

Residual Swin Group
  W-MSA
  SW-MSA
  3×3 residual conv

3×3 Conv
  → 128 channels

PixelShuffle ×4
  → 256×256×8 residual

+ bicubic-upsampled MS
```

Swin 설정:

```text
C=64
heads=4
window=8
shift=0/4
MLP ratio=2
```

### 5.3 Case

| ID | Swin depth | 예상 Params | 성격 |
|---|---:|---:|---|
| **`S2_LR_SW2_W64`** | 2 | 약 0.20~0.30M | micro 기준 |
| 조건부 `S2_LR_SW4_W64` | 4 | 약 0.27~0.40M | 용량 확대 |

파라미터 근사:

```text
input Conv 24→64      ≈ 0.014M
Swin pair C64         ≈ 0.069M
residual 3×3 Conv     ≈ 0.037M
output Conv 64→128    ≈ 0.074M
기타 LN/bias          소량
```

### 5.4 판정

| HQNR | 판단 |
|---:|---|
| ≥0.950 | 매우 성공적; SW4 실행 |
| 0.945~0.950 | ultra-lite Pareto 유지 |
| 0.940~0.945 | latency 2~3ms 이하일 때만 유지 |
| <0.940 | LR-TinySwin 갈래 종료 |

PixelUnshuffle/PixelShuffle는 shape smoke만으로 위상 오류를 잡을 수 없으므로 다음을 필수 확인한다.

```text
PixelShuffle(PixelUnshuffle(x,4),4) == x
단일 PAN impulse의 출력 영향 좌표
PAN과 LRMS 각각에 대한 non-zero output gradient
512×512 FR 입력 window divisibility / padding
```

## 8. 예상 의사결정

| 질문 | 결과에 따른 결정 |
|---|---|
| SW2가 c6보다 좋은가? | 아니면 Swin 갈래 종료. 좋으면 capacity 확대 |
| SW4·SW6가 계속 좋아지는가? | 포화 직전 depth를 s1 Transformer 후보로 선택 |
| D024 vs BTL2 | 같은 params에서 HQNR–latency 우세 구조 선택 |
| W112·W96 | HQNR 동급 범위 안에서 가장 작은 width 선택 |
| LR-TinySwin | 별도의 0.2~0.4M ultra-lite Pareto 여부 판단 |

최종적으로 다음 세 지점을 확보하는 것이 목표다.

```text
1. c6 no-attention anchor                  ≈ 3.77M
2. HQNR 우선 Swin hybrid                  ≈ 4.0~4.8M
3. Swin 유지 경량 U-Net / LR-TinySwin    ≈ 2M / 0.2~0.4M
```
