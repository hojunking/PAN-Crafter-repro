# QRECON24-R1 — s1–s5 실행 방향·우선순위 조정안

**작성 기준일:** 2026-09-17  
**기준 자료:** 직전 37개 결과 분석·CSV, 이번 native Sheet 재조회에서 추가 확인한 2개 결과, 현재 저장소의 서버별 QRECON24 큐.  
**상태:** 운영·실험 편성 제안. 이 문서 작성으로 코드·큐·Sheet를 수정하거나 학습을 기동하지 않았다.  
**범위:** 고정 method의 하이퍼파라미터와 실행 순서 조정. 아키텍처·Teacher·loss 함수·gradient 경로는 변경하지 않는다.

> **결정 요약:** G23 재현, β=0.2의 반복 검증, 두 조건의 결합, 같은 LR의 q 대조에 자원을 앞당긴다. 기존 진행 중인 run은 끝까지 둔다. 남은 원계획을 전부 폐기하지 않으며, 효과가 엇갈린 edge×aligner LR의 확인 grid도 완결한다.

## 0. 실행자가 먼저 볼 요약

- **s1:** G23을 다른 seed에서 확인하고, 성공한 aligner LR 0.03에서 q/uniform/shuffle을 맞춰 비교한다.
- **s2:** seed777의 상반된 결과를 버리지 않는다. 작은 edge의 G13과 edge용 q 대조를 앞당긴 뒤 남은 grid를 마친다.
- **s3:** seed4321의 G23을 앞당기고, β=0.2 및 결합 후보를 넣어 같은 서버·seed의 2×2를 완성한다.
- **s4:** β=0.2의 세 α 조건 개선을 seed3407에서 확인한다. 기존 H11 반복의 우선순위는 낮추고 H13/H23을 추가한다.
- **s5:** LR 탐색을 더 넓히지 않는다. 이미 시작한 seed9091의 LR block은 마치고, seed9091·1103을 결합 후보의 대응 반복에 사용한다.

**이번 재편 전량은 42run:** 원계획 미등록 29run 중 **26run 유지·재배치**, **3run 보류**, **16run 추가**다. ‘42개를 모두 새로 추가’하는 계획이 아니다. 완료 등록 39개를 다시 학습시키지 않는다. 기본 캠페인 누적 관점에서는 68−3+16=81run이며, 버전 감사에 따른 조건부 재실행은 별도다.

**24시간 규칙:** 원래 QRECON24의 **서버당 누적 신규 학습시간 ≥24h**를 계승한다. 이번 문서 때문에 다시 24h를 0부터 세지 않는다. 24h는 중단 시각이 아니며, 대응 비교 묶음을 완료한 뒤 평가한다.

### 1.3 모든 서버에 rA=0.03을 일괄 적용하지 않는다

λE=.002에서 G23−G22는 s2 seed777에서 −.0031, s3 seed2026에서 +.0003이다. s1의 큰 개선만으로 보편적인 A LR을 확정하지 않는다. **같은 서버·seed의 0.01 기준을 반드시 남긴다.** [S37 §5]

작은 edge도 일괄 폐기하지 않는다. s3의 λE=.0006에서 G11/G12/G13은 각각 .9557/.9501/.9566이다. 이번에 추가된 **s2 G11은 .9555**로, 같은 작은 edge의 G12(.9524)보다 높다. 낮은 edge 자체가 나쁜 것이 아니라 **A LR과의 조합에 따라 다를 수 있다.** [S37 §6, N2]

### 1.4 낮은 전체 LR의 확대는 보류한다

s5 L050−L100은 seed2026에서 HQNR +.0003이지만 seed777에서는 −.0015이며, 후자에서는 RR 여섯 지표도 악화했다. 따라서 **seed1103까지 낮은 LR 전수 탐색을 계속하는 것보다 유력한 loss/LR 조합을 반복하는 데 우선순위**를 준다. 다만 이미 seed9091 baseline이 등록됐고 후속 run이 시작됐을 가능성이 있으므로, 그 LR block은 완결하도록 보수적으로 편성했다. [S37 §7]

## 2. 고정할 method — 숫자 2 제거 후의 정의만 사용

\[
d_T=\operatorname{sg}\frac{e_T}{e_T+\tau_R},\quad
 a_T=\operatorname{sg}\left[\operatorname{clip}_{[0,1]}
 \frac{[e_S-e_T]_+}{e_S+10^{-6}}\right],
\]
\[
H_i=\operatorname{mean}_p[(1+\alpha d_T)e_S],\quad
K_i=\operatorname{mean}_p[\beta(1-d_T)a_T|Z_S-Z_T|_{\rm bandmean}],
\]
\[
s_i=\operatorname{sg}\frac{q_{\rm ref}}{q_{\rm ref}+q_T(i)},\qquad
q_{\rm ref}=0.3276133416220546.
\]
\[
L_U=\frac1B\sum_i[H_i+K_i+\lambda_Es_iE_i],\qquad
L_A=\frac1B\sum_i s_iH_i.
\]

U-Net에는 ∇θ L_U만, aligner에는 ∇φ L_A만 적용한다. **L_U+L_A를 더해 전체 파라미터에 backward하지 않는다.** 같은 forward·같은 pre-step 파라미터에서 gradient를 각각 계산한다. α는 두 모듈의 hard에 함께, β는 U soft에만 직접 들어간다. λE는 U edge에만 직접 들어간다.

| 항목 | 고정 계약 |
|---|---|
| Teacher | T0 W112–D123 A/U frozen, 자체 고정 정합 경로. 기존 자산 hash 확인 |
| Student | W104–D121, fresh U + T0 A 전체 복사. 원래 입력·MS/GT 좌표 유지 |
| τR | 0.012463942170143127 |
| q | 기존 Teacher q cache, train 중앙값, 분자 **1**. 추가 confidence head/temperature/threshold 없음 |
| Uniform 대조 | **0.5**, 1이 아님. 평균을 매 batch 1로 만드는 재정규화 없음 |
| Shuffle | 연속 s_i를 기존 e-decile×augmentation stratum에서 permutation51515로 교환 |
| Edge | GT signed Scharr /32의 기존 E_i. λE는 **절대값** |
| Student A 감독 | q-weighted GT hard만. soft/edge 직접 gradient 없음 |
| Student offset/jitter | 없음. Teacher 사전학습의 L1E4 이력은 유지 |
| 학습 | 50K, batch48, AdamW WD .01, warmup100+기존 cosine, 기존 precision·optimizer 설정 |
| Aligner LR | ηA(t)=rA·ηU(t). 예측 shift 자체에 rA를 곱하지 않음 |

**이 문서의 .0006/.002/.006은 이미 분자 2 제거에 맞춰 환산한 값이다. 다시 2배 하지 않는다.** 원래 계획서의 .0003/.001/.003 또는 uniform=1이 남아 있는 설명은 이번 실행값으로 쓰지 않는다. 현재 repo 큐의 머리 주석이 새 규약을 명시한다. [Q1–Q5, I §9.1]

## 3. 바꿀 것과 바꾸지 않을 것

**바꾸는 것:** 미시작 run 순서, 대응 확인 seed의 일부 배분, 기존 범위 안의 β=.2와 rA=.03 결합, 같은 LR에서의 q 대조.

**바꾸지 않는 것:** loss 식·gradient 경로·Teacher·아키텍처·q 정의·GT edge 연산·50K horizon·주 평가 규약. 새 geometry/variance/feature KD, Student offset 복구, 전체 aligner 동결을 주력으로 전환, 임의의 긴 fine-tuning은 이번 재편에 넣지 않는다.

전체 LR의 새 범위와 β>.2, rA>.03 탐색도 이번에는 추가하지 않는다. frozen·uniform·shuffle은 효과를 분리하는 대조군이다.

## 4. 신규 profile은 세 개만 정의한다

기존 H/G/L profile을 다른 서버·seed에 추가하는 것은 새 loss를 만드는 일이 아니다. **새 파라미터 조합/대조 정의는 아래 세 개뿐**이다. 아직 repository에 등록하거나 실행한 것이 아니다.

| 신규 profile | λE | rA | α | β | U peak LR | A peak LR | A hard 가중 | U edge 가중 |
|---|---:|---:|---:|---:|---:|---:|---|---|
| **B20A03** | **.002** | **.03** | **1** | **.2** | **1e-4** | **3e-6** | 실제 q | 실제 q |
| **A03_UNIF** | .002 | .03 | 1 | .1 | 1e-4 | 3e-6 | **상수 .5** | 실제 q |
| **A03_SHUF** | .002 | .03 | 1 | .1 | 1e-4 | 3e-6 | **조건부 shuffle** | 실제 q |

B20A03은 G23에서 β만 .2로 올린 후보이며, H23에서 rA만 .03으로 올린 후보다. 기존 q 함수는 그대로다. A03_UNIF/A03_SHUF는 G23과 LR·β·λE가 같고 **A의 q 연결만** 바뀐다.

기존 profile의 숫자는 다음 규칙을 사용한다.

| 기존 profile | λE | rA | α | β | U LR |
|---|---:|---:|---:|---:|---:|
| Gij | i=1/2/3 → .0006/.002/.006 | j=1/2/3 → .003/.01/.03 | 1 | .1 | 1e-4 |
| Hij | .002 | .01 | i=1/2/3 → .5/1/1.5 | j=1/2/3 → .05/.1/.2 | 1e-4 |
| A_UNIF / A_SHUF | .002 | .01 | 1 | .1 | 1e-4 |
| A_FREEZE | .002 | **0, A 완전 동결** | 1 | .1 | 1e-4 |
| E_UNIF / E_SHUF / ALL_UNIF | .002 | .01 | 1 | .1 | 1e-4 |
| H_BETA0 | .002 | .01 | 1 | **0** | 1e-4 |
| L100 / L070 / L050 | .002 | .01 | 1 | .1 | 1e-4 / 7e-5 / 5e-5 |

A_UNIF/A_SHUF는 A만 변경, E_UNIF/E_SHUF는 edge만 변경, ALL_UNIF는 둘 다 상수 .5다. **G22=H22=L100**은 같은 수학적 설정이며 동일 서버·seed에서 중복 실행하지 않는다.

## 6. 어떤 비교가 완성되는가?

### 6.1 Aligner LR×soft의 2×2

모든 셀은 λE=.002, α=1, U peak LR=1e-4, 같은 q 식·학습 경로다.

| | β=.1 | β=.2 |
|---|---|---|
| rA=.01 | G22 또는 H22/L100 | H23 |
| rA=.03 | G23 | **B20A03** |

| 같은 서버·seed block | 이미 있는 대응점 | 추가/우선 실행으로 채우는 점 |
|---|---|---|
| s3 · 4321 | G22 | 기존 G23 + 신규 H23/B20A03 |
| s4 · 1234 | H22, H23 | 신규 G23/B20A03 |
| s5 · 9091 | L100 | 신규 G23/H23/B20A03 |
| s5 · 1103 | 아직 없음 | 기존 예정 L100 + 신규 G23/H23/B20A03 |

이 네 block은 Student seed가 서로 다르지만, 하나의 T0를 공유한다. 서버 효과를 없애기 위해 먼저 **각 block 안의 대응 변화**를 계산한다. s4의 G23 seed1234를 s1의 G23 seed1234와 함께 독립 seed 두 개로 세지 않는다.

같은 평가 규칙의 HQNR을 H(·)로 표기하면:

\[
\Delta_{\beta\mid A=.01}=H(H23)-H(G22),\quad
\Delta_{\beta\mid A=.03}=H(B20A03)-H(G23),
\]
\[
I=H(B20A03)-H(G23)-H(H23)+H(G22).
\]

I는 이 grid에서의 상호작용을 요약하는 값이다. 각 run에서 따로 선택한 best의 차이이므로, 그 값만으로 물리적 원인·통계적 유의성을 확정하지 않는다. 같은 식의 last/late6도 보조적으로 계산하되, 사용자 목표를 사후에 바꾸지 않는다.

### 6.2 β=.2의 반복은 ‘좋은 값 하나’가 아니라 쌍으로 남긴다

s4 seed3407에서 **H12↔H13, H22↔H23, H32↔H33** 세 쌍을 확보한다. seed1234에서 관측한 3/3 양성의 방향이 다른 초기값에서도 유지되는지 본다. 단일 H13만 추가해 다른 seed의 H22와 빼는 방식은 쓰지 않는다.

### 6.3 q 효과는 별도 검증이다

s1 G23/A03_UNIF/A03_SHUF는 rA=.03, β=.1을 같게 둔다. s2 G22/E_UNIF/E_SHUF/ALL_UNIF는 rA=.01, β=.1을 같게 둔다. 따라서 **A의 q 배분과 U edge의 q 배분을 따로 검토**할 수 있다.

G23이 목표를 넘었다는 사실은 ‘현재 q를 사용하는 조합으로 목표 달성 후보가 생겼다’는 근거다. q 자체의 우위를 주장하려면 이 대조와 반복이 필요하다. 실제 q 가중은 약 .397–.548로 완만한 범위이며, uniform .5가 정확한 batch-mean 정규화는 아니라는 점도 유지한다. [I §9–9.1]

### 7.2 목표 selector는 원래 best와 별도로 수행

현재 도구에 존재하는 명령 형식은 다음이다. 운영 GPU가 학습 중이면 같은 GPU에 재평가를 중첩시키지 않고 case 경계에서 실행한다.

```bash
python tools/qrecon24_select.py \
  PAKD50_QRC24_S1_G23_W104_D121_WV3_T0_S1234_FRESH50_v1 \
  --official --threshold 0.9585 --device cuda
```

s4 H31에도 동일 형식으로 수행하여 **반올림 전 raw HQNR이 하한 이상인지** 확인한다. H31의 .9585 표시만으로 엄격한 적격 판정을 대신하지 않는다. 다른 기존 run에서 적격 후보가 나오면 같은 selector를 적용한다. [SEL]

- 같은 checkpoint에서 **HQNR≥.9585를 먼저 만족**한 뒤 공식 RR **SCC→ERGAS→PSNR→SAM→Q8→SSIM** 순으로 고른다.
- RR 목표: SCC>.988, ERGAS<2.040, PSNR>37.956, SAM<2.787, Q8>.922, SSIM>.976. 논문 표시 정밀도의 동률과 고정밀 strict pass를 구분한다. [PC Table 1]
- 기존 `best_hqnr`, raw-max, exact50K와 late6는 그대로 남긴다. 새로운 목표용 선택을 기존 best 행에 몰래 덮어쓰지 않는다.
- 적격 후보 중 공식 RR가 누락되면 ‘완료된 최적 선택’으로 표시하지 않는다. 학습 중 proxy SCC·ERGAS와 공식 RR를 섞지 않는다.
- **후반 평균은 안정성 진단**이다. 현재 개발 목표의 기준을 best에서 plateau로 자동 교체하지 않는다.

이 평가는 새로운 checkpoint 학습이 아니지만 GPU·추론 비용이 든다. §10의 학습시간이나 run당 10분 기본 후처리 안에 무조건 포함됐다고 가정하지 않는다.

## 8. 시작 전 비교 가능성 확인 — 방법 변경 없이 처리

### 8.1 s1 첫 G22@1234의 버전 충돌

구현 노트는 이 ID가 분자 2가 있는 코드에서 먼저 시작됐다고 기록하고, 현재 Sheet 설명은 분자 1·λE=.002를 표시한다. **실제 시작 시 저장된 manifest/로그가 우선**이다. [I §9, S37 §3]

| 감사 결과 | 처리 |
|---|---|
| 단일 정의의 factor=1, λE=.002 run임이 확인 | 유효한 새 방식 결과로 보존. 근거 manifest 연결 |
| factor=2 또는 중간 정의로 학습 | 구버전 결과로 보존하고 새 방식 대응 분석에서 제외 |
| 중간 resume에서 정의가 섞였거나 증거 부족 | 버전 미확정으로 별도 표기. 정상 비교의 기준으로 쓰지 않음 |

필요할 때만 **같은 seed1234의 새 방식 G22를 새로운 ID로 1run 추가**한다. 기본 42run에는 넣지 않았다. 기존 ID·결과·로그를 삭제하거나 현재 config로 과거 metadata를 덮어써 해결하지 않는다. s1의 G23 재현과 rA=.03 q 대조는 이 감사와 별도로 진행 가능하다.

### 8.2 다른 release·호스트

s2에는 다른 branch/release SHA가 기록돼 있다. 예를 들어 신규 G11은 `672ccf541ea7`이다. repo main을 조회했다는 것만으로 해당 서버의 실행 정의까지 같다고 인증할 수 없다. **training-start resolved config, trainer/criterion 차이, Teacher/cue/init/data/evaluator hash**를 확인한다. 미확인 diff를 ‘metadata만 변경’이라고 단정하지 않는다.

s5는 초반 Train(h) 2.29–2.58에서 최근 1.46–1.63으로 달라졌다. 시간 단축이 loss 효율 개선인지 환경·기록 조건 변화인지 확인되지 않았다. 새 실험에는 성능 비교의 동일성과 시간 추정의 재측정을 각각 요구한다.

새 profile 등록 때문에 **trainer 수학·precision·optimizer 정책을 바꾸지 않는다.** 운영/registry 수정만으로 이전 run의 정의와 동등함을 확인하면 기존 완료 기준을 재사용한다. 정의가 달라진 경우 해당 block의 기준 run도 새 release로 재확보하고 그 비용을 추가한다.

## 10. 소요시간 — 지금부터 24h를 새로 예약하는 계획이 아님

표의 완료시간은 **39개 Sheet Train(h) 합**이며, local ledger의 완료·학습/후처리 구분을 최종 기준으로 삼는다. 미등록 실행 중 run의 이미 사용한 시간은 별도다.

대용 시간: s1 trainable 2.42h / frozen 2.15h, s2 2.56h, s3 1.47h, s4 1.51h. 모두 이번 QRC24 기록에서 가져온 보수적 대용값이다. s5는 최근 1.46h와 이번 campaign의 느린 2.58h를 **두 시나리오**로 사용한다. 신뢰구간이나 보장 상·하한이 아니다.

| 서버 | 현재 등록 Train(h) 합 | 남은 편성 | 남은 전체 학습량 대용 | 현재+남은 학습량 대용 | 남은 여유 포함 예약 |
| --- | --- | --- | --- | --- | --- |
| s1 | 14.08h | 8 | 19.09h | 33.17h | 24시간 14분 |
| s2 | 15.28h | 6 | 15.36h | 30.64h | 19시간 26분 |
| s3 | 14.66h | 10 | 14.70h | 29.36h | 19시간 18분 |
| s4 | 15.09h | 9 | 13.59h | 28.68h | 17시간 48분 |
| s5 | 13.23h | 9 | 13.14h–23.22h | 26.37h–36.45h | 17시간 16분–29시간 22분 |


예약식은 기존 QRECON24와 같은 **`1.20 × 남은 학습 대용시간 + run당 10분`**을 한 번만 적용했다. 이미 여유가 붙은 과거 예약을 다시 곱하지 않는다. s1은 7×2.42+1×2.15=19.09h다.

**남은 전체 학습량은 75.88–85.96 서버·시간**이다. 각 서버가 지금부터 모든 남은 run을 새로 시작한다고 놓은 예약 최대값은 약 **24시간 14분–29시간 22분**이며, 다섯 서버의 시간을 합친 값이 병렬 경과시간은 아니다.

이 표에 현재 진행 중 run이 포함돼 있다면 **그 run은 전체 시간 대신 남은 시간만 계산**해야 한다. 현재 run의 잔여를 표에 또 더하면 이중계산이다. 이 문서는 PID/현재 step을 읽지 못했으므로 정확한 종료 시각은 제시하지 않는다.

다음은 별도 비용이다: 코드·자산 감사, 새 profile의 gradient/config 검사, 공식 RR 후보 재평가, cue 검증·파일 전송, 조건부 기준 재실행. 정기 학습 평가가 기존 Train(h)에 포함되어 있다면 다시 더하지 않는다.

**누적 최소 24h:** 본 재편을 완결하면 현재 대용값상 모든 서버가 원래 campaign의 24h를 넘는다. s1의 의심 G22 2.42h를 유효 method 집계에서 제외해도 30.75h로 넘는다. 그래도 운영 ledger에서 재확인하며, 시간을 채우려고 이미 같은 ID로 완료한 run을 중복 실행하지 않는다.

## 11. 운영 반영 규칙 — 큐 파일 하나만 바꾸지 않는다

### 11.1 안전한 전환

1. **현재 active run과 PID·step·SHA를 각 서버에서 확인한다.** 완료·실행 중·실패·대기를 분리한다. Sheet의 마지막 행 다음 run을 현재 실행 중이라고 추정하지 않는다.
2. 이 문서의 새 profile/서버·seed 조합을 generator/registry에 등록하고, 바뀌지 않아야 할 loss·gradient 설정을 검사한다. 기존 진행 중 config는 재생성하지 않는다.
3. 검증 release를 별도 작업트리에서 준비하거나 현재 run 종료 경계에서 반영한다. 실행 중인 작업트리에 무조건 pull하지 않는다. 새 코드의 core 학습 동등성을 기록한다.
4. **generator의 priority, `config/queues/qrecon24_s*.txt`, 서버 로컬 active queue, mandatory 목록, reservations, handover, waiter가 보는 목록**을 같은 revision으로 갱신한다. 완료 history는 그대로 남긴다.
5. 현재 run이 완료되면 조정 순서의 미완료 항목으로 이어간다. 신규 16개는 snapshot에 없는지 재확인하고, 그 사이 완료된 항목은 건너뛴다.

현재 `tools/qrecon24_switch.sh`는 큐 파일과 생성기 순서의 일치를 검사하고, `work_dir/cases_queue_handover.txt`를 통해 case 경계 인계를 지원한다. `--extend`는 원래 mandatory가 끝나야 허용되는 구조다. 따라서 **보류한 항목이 mandatory에 남으면 끝없이 기다리거나 다시 편성될 수 있다.** 이번 재편을 지원하도록 관련 목록을 일치시킨 뒤 기존 switch의 검사를 사용한다. [SW]

기존 `--dry-run`은 현재 구현에 존재하지만, **이 문서의 신규 profile을 자동 구현하는 옵션은 아니다.** 지원하지 않는 `--adjust` 등의 명령을 만들어서 호출하지 않는다. 큐 수정·학습 실행은 운영자가 수행한다.
